# S0 SONG_SELECTION — Selection Method v0.1

## 1. Start from trusted evidence, not a generic trend list

Primary source remains the user's trusted core-account ecosystem.

Historical rule retained:

ALL CORE ACCOUNTS -> SONG POOL  
ACCOUNT ROLE -> SIGNAL INTERPRETATION / WEIGHT  
NOT -> EXCLUSION

A visual account can still contribute valuable music candidates.

## 2. Normalize work-level observations into SONG_FAMILY

Different works may use:
- original;
- cover;
- remix;
- electronic version;
- live version;
- edited excerpt.

At S0:
- compare at SONG_FAMILY level;
- keep each concrete work identity intact;
- do not pretend variants are the same audio.

Exact Audio Version begins only in S1 after the user chooses one concrete work.

## 3. Build candidate evidence

For each viable candidate capture only what helps selection:

- song family;
- core account(s);
- concrete work link/ref;
- approximate/captured duration when known;
- cross-account repeat signal;
- lyric/semantic visual hook;
- animation fit;
- motion fit;
- reference usefulness;
- prior project usage;
- known version ambiguity;
- major risk.

Do not perform full lyric/beat/timeline analysis here.

## 4. Qualify against the current project goal

The same song can be suitable for one experiment and poor for another.

Examples of goal dimensions:
- high-motion test;
- healing/bright visual;
- strong character acting;
- strong lyric hit;
- new-project novelty;
- regression benchmark.

The goal changes candidate qualification, not the source-of-truth pool.

## 5. Deliver no more than three primary candidates

Each primary candidate should let the user answer:

- What song is this?
- Which exact reference should I open?
- Why is it here?
- What is the main production opportunity?
- What is the main risk?
- Has it been heavily used before?

Do not bury the Human Gate under a long catalog.

## 6. Human Reference Gate

The model does not choose the production song.

The user may:
- select one concrete work;
- reject all candidates.

If one is selected:
SONG_SELECTION -> SEALED candidate -> S1 PROJECT_AUDIO may begin.

If all are rejected:
S0 stays open and runs the next candidate round from the trusted pool.

## 7. Why this split matters

S0 is a selection problem.

S1 is a truth-locking problem.

Keeping them separate prevents one giant stage from mixing:
discovery + recommendation + user taste + audio extraction + timeline analysis + downstream production state.
