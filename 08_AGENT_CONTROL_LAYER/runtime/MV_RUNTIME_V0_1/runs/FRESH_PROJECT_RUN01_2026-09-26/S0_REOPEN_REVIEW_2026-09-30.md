## 原判断哪里出了问题

| 原做法 | 实际能证明什么 | 漏掉的条件 | 修订 |
| --- | --- | --- | --- |
| 标题中文、官方页面有 28 行歌词 | 元数据与书面歌词存在 | 音频里是否实际唱出且能辨认 | 主候选先检查真实音频中的连续中文句子 |
| 根据书面歌词给出 HIGH 视觉适配 | 文字有可视化潜力 | 听觉内容是否足以支撑歌词驱动 MV | 先过可听内容，再评语义与视觉 |
| 公共完整播放页可取得 MP3 | 获取路径可行 | 取得的来源是否适合目标模式 | 获取成功与内容合格使用不同状态 |
| 强制对齐 28 行、时间单调 | 算法可放置给定文字 | 实际词语是否出现在这些时间 | 对齐只在真实词语证据之后使用 |
| AUTO_CONFIRMED_FOR_TEST 封存 | 测试允许自动确认选择 | 资格证据是否齐全 | 自动确认不得豁免资格门禁 |
| 为新鲜度挑选近期独立音乐 | 有平台近期日期 | 不是首次发行日期、缺乏核心账号出处 | 记录首次发布/平台上架区别；保留核心来源规则 |
| S1 持续换窗口 | 局部时间调整可继续 | 是否已是选歌/素材适配问题 | 用户否决和重复歌词歧义触发上游回退 |

因此责任包含 S0 漏检和 S1 失败回传不及时。上一轮虽更正对齐并制作全曲参考图，但可听门禁仍不足，继续交付窗口没有解决原素材资格问题。

## 阶段边界的明确变更

旧冻结 v0.3 文件保留。新增仅适用于本 run 的 v0.4 addendum：S0 允许有限参考音频检查，只为资格判断；每个候选最多 90 秒、3 个 30 秒窗口，本轮公开请求最多 1500000 字节。音源完整获取、精确版本锁定、全曲时间轴、正式截取仍属 S1。参考检查中的定位时间不是制作片段时间。

旧“主候选必须 1–3 个”改为“合格候选 0–3 个”；没有足够证据就交付不足状态。中文限定、历史去重、九核心账号全部入池、核心/补充来源区分、人工锁歌、S1 后才能 S2 全部保留。2026 新歌仍是次级偏好，不代替歌词适配；无明确首次发布证据时不称新歌。
