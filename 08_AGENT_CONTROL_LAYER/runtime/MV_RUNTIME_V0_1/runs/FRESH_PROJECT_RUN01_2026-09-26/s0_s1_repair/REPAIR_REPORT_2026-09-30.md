# S0 为什么堵塞，以及本轮修复

本轮问题同时涉及选歌适配、历史能力判断和最近新增的阶段边界。原《告别》只有歌曲/歌词网页和来源身份的证据，不能据此证明实际选中版本有适合歌词驱动 MV 的清晰演唱。三次人工试听已否决其本轮适配性，继续换时间窗没有解决选歌问题。该曲和同一源哈希继续排除；不推断所有版本都无歌词。

## 回查得到的原因

| 问题 | 历史证据与表现 | 本轮处理 |
| --- | --- | --- |
| 把控制层重测当成自动制作已跑通 | `S0_S1_CONTROL_RETEST_RUN01.md` 的 KNOWN_GOOD_REPLAY 使用用户提供的21.360907秒片段和测试自动确认；只证明控制协议 | 明确自动获取、内容筛查、时间线和人工锁定是不同检查 |
| S0 与 S1 边界被上一轮改错 | 冻结 S0 v0.3 只选 SongFamily；run-local v0.4 和 `s0_reopen/s0_gate.py` 却把实际试听当成候选前提 | 承认并撤销这个新增阻塞；S0 做方向候选，实际来源和早期歌词筛查进入 S1 |
| 核心标签严格字符串比较及补充来源无测试出口 | 上一轮 gate 只允许 `VERIFIED_CORE`；历史核心标签、`NO_EXCLUSION_IN_CURRENT_LEDGER` 均被误挡 | 核心标签归一，保留历史去重；补充来源必须显式开启且标记 SUPPLEMENTAL_TEST |
| 核心链接返回空壳网页 | 三首核心复核记录均为 HTTP 200 HTML shell，无播放器/实际音频证据 | 保留方向资格；来源继续恢复，可明示同曲音频与独立视觉参考，禁止把网页当媒体 |
| 验证器读已过期交付 | 旧 `validate_fresh_run.py` 固定读取早期 `S1_DELIVERY.yaml`，要求 SEALED，并忽略人工撤回后的当前状态 | 改读当前状态和当前 S0 交付；状态一致性 PASS 不再表示音频 PASS |

历史合同：[S0 v0.3](../../../stages/00_SONG_SELECTION/S0_STAGE_CONTRACT_v0.3.yaml)、[S1 v0.4](../../../stages/01_PROJECT_AUDIO/S1_STAGE_CONTRACT_v0.4.yaml)；[控制重测报告](../../../S0_S1_CONTROL_RETEST_RUN01.md)与[参考恢复协议](../../../stages/00_SONG_SELECTION/S0_RUN01_B_REFERENCE_RECOVERY.md)。本次只改当前 run 的实现、规则补充和状态，没有改冻结共享合同或旧项目 tracker。控制重测、参考恢复协议和公开来源事实保留为历史证据。

## 已实现

- `candidate_intake.py`：S0 方向筛选、核心优先、SongFamily 去重、最多3首；显式测试来源；S1 内容筛查；人工否决优先；被拒哈希缓存；最多每曲2个来源、3首方向的失败出口；最终音频门槛。
- `s0_reopen/s0_gate.py` 改成方向筛选兼容入口，旧 v0.4 补充标记为 SUPERSEDED。
- `validate_fresh_run.py`：当前状态与交付一致性检查，加单元回归检查。旧验证器保存在 `validate_fresh_run_v0.1_historical.py.txt`，不再执行。
- `run_validation.py`：读取真实本地媒体，核对文件哈希和字节数；识别报告必须绑定同一媒体，窗口不重叠并覆盖全曲；不能仅凭 JSON 的 acquired/PASS 字段冒充执行。
- 原音源技术 PASS、三次人工 FAIL、历史交付均保留；交接文件顶部已改指向当前状态。

S1 早期自动筛查采用“至少2个独立窗口各有至少6个连续中文字与可信歌词匹配”的实验性启发式，只决定是否值得继续完整分析，**不是经过校准的可听性指标**。最终仍需可听具体歌词、来源版本锁定、完整时间线、短句边界和人工 Audio Lock。ASR/LRC/歌词网页均不能单独封存。

## 实际测试结果

公开测试来源：[想想XiangXiang《一个人在家》](https://xiangxiang.bandcamp.com/track/-)，track id `985094992`。这是补充测试源，不是正式核心选歌；上轮已确认存在2024年公开发表记录，2026平台日期不当作首次发行。

- 完整获取3,944,279字节；解码时长246.4615秒。媒体 SHA256：`2c47c8baa120908d8662e33cba72dac52763e2b1e3a734584501ab7e10113ad9`。
- 前1,500,000字节与上轮同曲样本一致；实际本地文件哈希与本次报告一致。
- 全曲9个不重叠窗口使用 SenseVoice 盲识别，未向识别器提供歌词。识别后才做繁简归一及可信歌词连续匹配；5窗提供支持，最长连续匹配9字。
- 0–30秒无识别中文；不能直接从开头选制作片段。早期筛查结果是 `FULL_ANALYSIS_ELIGIBLE`，没有精确歌词时间线、最终选段或 Audio Lock。
- 23项单元检查通过；包括错误文件、缺失媒体、异源识别报告、重复窗口、旧封存、测试支线越权以及人工拒绝优先等行为。

`REAL_VALIDATION_RESULT.json`、`full_source_meta.json`、`full_scan_summary.json` 提供可核对的结果。仓库只提交代码、来源元数据和非全文识别摘要；完整歌曲、完整歌词、原始逐字识别稿及模型留在临时执行环境。
