# 动态能力评估：已验证的内容与本项目的上限

这不是视频生成模型评测，也不是所有代码动画的普遍极限。结论只针对当前 GPT 插画素材、Canvas 合成、这首歌和本轮试片。

| 制作条件 | 可追求的结果 | 当前证据与限制 |
| --- | --- | --- |
| 沿用现有六张主要单姿态插画 | 镜头有空间、风水有层次、物件有事件的电影插画 MV | 前一版已实现。追加运镜不能凭空得到可信的手臂动作、脚步和转身 |
| 增加相同角色的高分辨率动作姿态、过渡画与拆层 | 人物动作可读、接触与惯性可信的 2.5D 情绪动画短片 | 本轮只验证一组抬手/攥围巾的概念。其余事件、连续性和整片尚未验证 |
| 为复杂动作补足视角、遮挡、关节与逐帧过渡，投入完整动画制作 | 可以继续做步态、身体转动、复杂互动和更大的镜头变化 | 理论制作路径；所需画工、资产和动画劳动显著增加。不能靠给单张图加提示词自动兑现 |
| 另行验证关键动作的视频生成，代码负责编辑/字幕/节奏 | 有机会改善连续的身体表演 | 本轮未使用视频模型，未验证本角色、这首歌或身份稳定性，不能当作现成承诺 |

因此，当前路线值得追求的项目目标是“可读人物表演 + 有动静反差的 2.5D 电影插画动画”。目前不是帧率卡住上限，而是缺少动作状态和可靠的中间状态。

## 5.11 秒实际实验

从原音源截取 16.25–21.360907 秒，保留“怪我太过念旧 / 迟迟不肯退后”。在相同人物和服装参考下生成八个姿态，固定头肩位置，依次显示手抬起、接触围巾、攥住的变化。初版切手部细节再回宽景；独立审片指出额外切换、近景软化和手放下的接续问题，修订版取消两次切换，以同一中近景保留攥围巾终态。没有走路、没有身体整体滑移模拟走路、没有调用视频模型。

图集实际是 1536×1024，四列两行，每个姿态只有 384×512。镜头中人物放大 3.2 倍；初版细节插入再放大 1.35 倍，独立审片认为其清晰度弱于原版，这个插入已取消。正式近景仍需要更高分辨率的独立姿态。提示词要求更大图集并不等于工具实际输出更大分辨率；必须以返回文件为准。

视频为 1080×1920、30fps、153 显示帧；动作只有八个原始姿态，少量帧混合不能使它成为 30fps 的自然逐帧表演。实际可读的是手从低位抬起并抓住围巾；身体重量、明显内收和自然缓入缓出仍不充分。

初版技术 QA 没有页面报错，重复渲染一致，没有静止帧对；但动作段有五处突变提示：局部时间 0.482、1.102、1.240、1.447、1.929 秒。最后一处对应近景硬切，其余姿态交接不能用平均变化量证明顺滑。独立审片确实发现跳姿态与手部重影。修订版数据见 `verification/qa.json`；剪辑修订无法凭空补出缺失的动作中间画。原版“画面一直动”的 QA 也不能证明人物表演足够。

最终判断以 `INDEPENDENT_REVIEW.md` 为准。试片是概念验证材料，不应直接替代上一版完整 MV。整片升级应先解决独立高分辨率姿态、连贯过渡、接触位置及景别匹配，然后按 `DIRECTOR_DYNAMIC_PLAN.md` 执行。
