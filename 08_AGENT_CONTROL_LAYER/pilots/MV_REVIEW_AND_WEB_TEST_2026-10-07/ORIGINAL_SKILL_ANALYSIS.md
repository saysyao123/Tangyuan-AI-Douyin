# 源码诊断与原技能适配

证据对象：Run04 `engine/scenes/dynamic_mv.js`、`art_core.js`，Run04独立审片，以及2026-10-07用户反馈。技术证据和审美判断分别保存。

## 现象 → 原因 → 修复 → 验证

| 现象 | 原因与源码证据 | 待验证修复 | 验证方法 |
|---|---|---|---|
| 开头同图反复改变景别 | `opening()` 在1.35s由约z1.12跳至1.78；`longing()`在2.5s由约1.88重设1.40。主要是整幅位图裁切，没有新视角数据 | 0–5.75s共用固定构图，人物／断线／风承担事件 | 比较旧片开头与固定版，用户审片确认去除无因果重复变焦 |
| 扶围巾期间先推再拉 | `gesture()`的两项smoothstep在lt2.5s换方向；与L07/L08歌词边界绑定，未由动作触发 | A全程固定；B扶住后一次约3%微推并保持 | 原动作、音频、字幕不变，A/B只改相机 |
| 室内动幅叠加 | `empty()`外层lens + `A.room()`内部camera，相机有两个入口 | 场景只绘制世界，viewport唯一入口 | 检查绘制调用栈、相机参数与镜头边界连续性 |
| 飞照似跟拍但空间重置 | `escapedPhoto(detail=true)`重新设中心、比例；lt1.92起人物消失 | 固定中近景保留人物＋照片；或明确两个分镜，不能冒充连续跟随 | 世界坐标／手与照片关系及切镜头前后静帧检查 |
| 运动QA通过而用户否定 | 全画面平移缩放本身能增加帧差；稳定、无黑帧不能证明导演动机 | 检查相机动机、方向反转、同图重复景别；人物运动脱离相机单独审 | 用户审美结论为最终门，技术检查保持独立 |

上述倍率跳变由源码参数计算，不代表真实摄影透视变化；切镜头可以合理，但此处需补足景别切换的叙事目的。

## 成功机制

`gesture()`八帧起点[0,.42,.66,.87,1.03,1.19,1.36,1.56]，L07/L08共用全局动作时间，末帧保持。手从低位到接触围巾形成可辨认事件，头手基本不做背景式摇摆，尾部有限风动做次级运动。用户认可的是动作效果；不声称已验证自然连续解剖运动。八帧间短混合有双影风险，后续另开实验，不能为了修它同时改相机并破坏对照。

## 原技能读取与适用范围

本轮查阅本地 `huashu-art-motion/SKILL.md`，`references/02-机制.md`、`04-纯代码绘制.md`、`06-口播驱动的艺术短片.md`、`07-正面经验.md`、`10-角色.md`、`12-口播整片与经验回流.md`。

1. 02的艺术史速通机制是固定骨架、角色事件、母题循环、风格转场及节拍。提取机制，不把15秒16时代的节奏、每幕母题数量或128BPM写成抒情MV配额。
2. 04要求运动落在视觉焦点，07第29条允许按语法静止。手、照片、围巾负责主事件；空椅和完成动作后的停留可以成立，不追求帧差越大越好。
3. 10明确AI姿势帧＋代码合成，有限动画无需假称连续补间。本项目成功动作支持此分工；优先复用冻结帧而非重新生成已认可角色。
4. 06标记为待验证方法草案。大世界＋视口、屏幕尺度笔触适合可重新绘制的世界；本项目按用户要求采用生成插画，不能把平面缩放称为真实空间摄影，也不能继承矢量任意放大的优势。
5. 07第27条要求相机由全片时间统一管理，转场只合成；12要求动作依据内容、字幕区约束相机。落实成世界坐标、唯一相机入口、字幕独立坐标层。
6. 07第38条“只进不退”针对横向长卷跟拍。此项目借鉴避免无因果回拉，不禁止所有有叙事动机的回拉。
7. 12要求冻结用户选定版本，经验记录现象、原因、修复、验证。此轮未修改原技能；私人反馈保留在项目，通用方法将来经新片实测后再考虑回流。

## 项目适配规则

先定义事件与一屏焦点，再考虑相机；同一图没有新事件／重点，默认固定。每次运镜五字段：purpose、subject、emphasis、start_end、stop_condition。字幕切换不自动改变镜头；相机不在场景内重复执行。需要新透视、遮挡或反应，先设计新构图或世界分层，再写运动。

现实上限：电影插画、有限角色动作、物件互动与克制镜头的短MV。连续走路、复杂转身、真实多角度跟拍，需要新素材或其他运动生成能力；扩大位图或增加提示词不能补出原图没有的信息。

这些是项目适配和待验证优化，不是已经修好的引擎或新的技能安装包。
