# HF03｜顺序错 → 流程重排｜Logic Spec v1.0

> 状态：语义重新对齐。  
> 注意：此前 `HF03 Tangyuan IP v1 / v3` 的视觉制作方法可保留，但其中“旧稿被真实录音替换”的语义不作为正确逻辑继续复用。

---

# 1｜原始口播对应事实

本段方法论：

> 录音转字幕时，如果一开始先把旧稿给AI看，AI可能被旧稿带着走。因为实际口述和旧稿不一定完全一致。后来换顺序：先别看旧稿，先独立听完整录音，弄清楚实际说了什么，再整理字幕。AI还是同一个AI，任务也还是同一个任务，只是顺序变化，结果不同。

---

# 2｜Teaching Truth

**不是“旧稿没用”。**  
**不是“用真实录音替换旧稿”。**  
**不是“换了一个AI”。**

真正要表达：

> **同样的 AI、同样的录音、同样的旧稿；改变的是旧稿介入流程的时机。**

一句话：

> **先听录音，再看旧稿。**

---

# 3｜Entities

- `真实录音`：事实源 / Source of Truth
- `旧稿`：参考材料 / Reference，不是事实源
- `AI`：同一个处理者
- `独立听写/ASR`：先还原实际口述
- `确认原话`：事实锁定点
- `整理字幕`：后续清理/格式整理

---

# 4｜Invariant

以下全部不变：

- AI没换
- 任务没换
- 真实录音没换
- 旧稿也没有被删除

---

# 5｜Changed Variable

唯一核心变量：

> **旧稿什么时候进入 AI 的上下文。**

错误：旧稿过早介入。  
正确：旧稿延后到真实录音已经独立听写并确认之后，再作为参考介入后续整理。

因此本段的核心 Motion Verb 是：

> **Delay / Gate + Reorder**

不是：

> Replacement / Swap

---

# 6｜Consequence

## 错误流程

```text
旧稿先进入上下文
↓
AI带着旧稿去听真实录音
↓
旧稿与实际口述有差异时产生先验干扰
↓
转写/字幕容易被旧稿带偏
```

## 正确流程

```text
真实录音
↓
AI独立听写
↓
确认“实际说了什么”
↓
事实锁定
↓
旧稿此时才允许作为参考介入
↓
整理字幕
```

---

# 7｜推荐视觉结构

## Anchor

`AI / ASR处理核心` 固定。

## Variable

`旧稿介入时机`。

## Signature Move

不是把旧稿推出去、把录音换进去。

而是：

1. 错误阶段：旧稿在时间轴上先于录音解锁，AI上下文已被旧稿占用；
2. 转折：旧稿被一个 `REFERENCE GATE / 暂缓参考` 门控住，但它仍然可见、仍然存在；
3. 真实录音先通过AI进入 `独立听写`；
4. `确认原话` 节点 Lock；
5. Lock 完成后，Reference Gate 才打开；
6. 旧稿从侧路接入 `整理字幕` 阶段，而不是重新接入“听写事实”阶段。

这样观众亲眼看到的是：

> **旧稿没有消失，只是晚一点进来。**

---

# 8｜文字优先布局

主标签必须大于图标：

- `真实录音`
- `旧稿（参考）`
- `AI 独立听写`
- `确认原话`
- `整理字幕`

辅助状态：

- `过早介入`
- `暂不参考`
- `已确认`
- `后参考`

图标只作为辅助识别，不承担理解入口。

---

# 9｜连接规则

错误阶段：

`旧稿 → AI上下文` 必须精确连入“参考/上下文入口”；
`真实录音 → AI听写入口` 是另一条独立入口。

正确阶段：

- `真实录音 → AI听写入口 → 确认原话` 为主路径；
- `旧稿` 在确认前不得连入听写入口；
- `确认原话` Lock 后，`旧稿（参考）` 才从侧路连入 `整理字幕`；
- 旧稿的侧路不能连到事实锁定前的节点。

---

# 10｜Resolve 文案候选

优先：

> **先听录音，再看旧稿。**

次级总结：

> **AI没换，材料没换，只是顺序换了。**

如只留一句，优先第一句，因为理解成本最低。
