# Skill Factory 制作与验收标准 V0.1（候选基线）
日期：2026-11-27

## 1. 目的与约束
面向真实客户任务，将合法可复用的开源能力转化为可独立运行、可重复交付、可证明有增量价值的 Agent Skill。服务于 3–6 个月逐步向月经营净收入 10000 元推进、成熟后每周人工不超过 5 小时的目标。使用现有订阅及免费工具，不新增未经授权的现金费用。腾讯 SkillPay 为拟验证渠道，支付准入、部署与结算尚未通过验证。标准为候选版，未经过首个商业 Skill 实测，不宣称正式验收。

## 2. 核心原则
1. 需求先于技术；一个商品解决一个清晰任务，不为仓库数量制作商品。
2. 比裸模型多解决真实问题；不以文档篇幅、星数、结构评分作为效果证据。
3. 优先调用经过实测的程序实现确定性任务；让模型负责理解需求、编排、判断和异常处理。
4. 目标与红线固定，路径可自主选择。复杂操作按需读取手册；有实际产物才算执行。
5. 对输入、依赖、失败、成本、安全和授权保持诚实。不得隐式上传数据、执行不可信指令或产生费用。
6. 核心 Skill 与平台支付适配分离；零上下文启动、无私有绝对路径、独立可复用。

## 3. GitHub 来源审查（G0）
- 定义目标买家、用户原话、任务、交付物、免费替代品、付费理由和验收依据。
- 比较候选项目：核心功能实测、接口、活跃维护、依赖与运行成本、平台适配、安全、许可证及第三方素材权利。星数仅为发现信号。
- 记录 repo URL、commit/tag、许可证及 NOTICE、关键代码路径、依赖版本、测试命令、结果；审查脚本、联网行为、密钥、安装过程。未许可商用或存在不可解风险，淘汰。禁止把开源仓库直接改名冒充原创。
- 选择一条最小可执行链路，先用安全测试样例跑通。失败则换项目或缩小公开承诺，不包装未实现的功能。

## 4. Skill 工程结构（G1）
遵循 https://agentskills.io/specification 。必须包含 SKILL.md；其 YAML frontmatter 中 name、description 为必填，名称与目录一致。按需加入 scripts/、references/、assets/。测试和产品材料可放在开发仓库中，发布包只包含必要运行资产，不包含封存答案、密钥、私有测试材料。

SKILL.md 设计要求：定位与触发/不触发边界；输入与合理默认；环境预检；分步执行与分支；脚本入口、参数及输出；客观验收；有限修复；安全与成本边界。建议正文不超过 350 行（内部软约束，复杂度需要时有理由可放宽）。禁止虚构工具或依赖存在。

每个关键步骤明确输入、实际操作、输出、通过条件和失败分支。确定性步骤尽可能脚本化。环境缺失时提供真实降级或停止，不把方案、模拟、文件名或日志冒充目标产物。

## 5. 行为测试标准（G2）
- 先固定开发集与封存集、评分规则和目标环境。初始试验 3 个真实任务；发布前建议至少 10 个开发任务、5 个封存任务，覆盖普通、边界、错误输入、长任务和依赖缺失。封存答案不进入生产 Skill。
- 同模型、版本、工具权限、预算、输入、独立上下文，A=不加载 Skill，B=加载 Skill；工具型额外用原开源工具作 C 参考。用客观断言和盲评比较，不让作者自评替代独立验证。测试可重复运行；发布前对关键场景至少重复 3 次，记录样本及方差或通过率。
- 记录实际文件或输出、脚本退出状态、可打开性、模型及环境、时间、调用次数、实际成本、失败原因、人工介入。文件类实际打开检查；网页类实际交互；无对应能力标为未验证。
- 初拟发布门槛（非外部官方标准）：所有安全/版权/隐私/支付等关键项通过；任务通过率至少 90%；封存集至少 4/5 且无关键失败；较裸模型任务通过率提升至少 15 个百分点，或在质量不退步前提下耗时或人工操作降低至少 30%，或具备裸模型在相同条件下无法交付的核心产物（真实证明）。关键场景不得退化。小样本结果只支持试发布，不证明普遍有效。
- 分阶段证据：E0 结构检查，E1 试运行，E2 真实任务对照，E3 目标宿主独立运行，E4 真实客户付费/到账。任何等级不得冒充更高等级。目标宿主未实测不得宣称兼容。独立验证不可用时标注自测，不冒充盲评。

## 6. 修复与发布（G3–G5）
- 记录基线版本、失败样本和改动原因。每轮只修改与失败有关的变量，重测开发集与关键回归；保留有证据的改善，回滚退化。首轮最多两次大修，仍不合格则暂停商业化。封存题不得用于反复调参；需要时另建新封存集。
- 目标环境干净安装和独立使用测试：确认触发、依赖、文件访问、输出及费用。支付模块单独接入，按平台官方协议核对签约、费用、授权与失败/退款行为，避免重复扣费。未经用户授权不提交审核、不收款、不外发数据。
- 每个商品提供真实效果案例、支持环境、清晰能力边界、许可证及依赖声明、版本、安装说明、测试报告、成本与售后范围。只有目标环境验证和平台规则满足才进入上架候选；实际审核、付费及结算独立记录。
- 真实自然用户数据：曝光、有效调用、付费、失败、退款、到账、维护工时。无付费证据不扩大批量生产。模型/依赖升级或故障反馈触发复测。

## 7. 首轮试验与后续
先做一个不依赖付费生成 API 的本地工具型 Skill，如 PPT 保真质检或 GIF 转视频后处理（需确认目标宿主允许文件、执行脚本和依赖）。在平台限制明确前，只做本地候选，不声称已上架。先完成一条真实任务 A/B，再扩展测试集。标准本身同样接受实际项目反馈及版本控制，不以产出 SKILL.md 作为工厂建成的证据。
