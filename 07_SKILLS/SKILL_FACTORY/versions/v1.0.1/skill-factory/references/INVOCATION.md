# 调用与续作

输入模式：
- BUILD: 调用 Skill Factory，把 <GitHub URL 或需求> 做成可执行 Skill。默认执行至实际可达的最高验收关卡。
- AUDIT: 调用 Skill Factory，审核这个 Skill，实际测试并提供失败证据，不改原文件。
- EVOLVE: 调用 Skill Factory，按失败记录优化这个 Skill，保留旧版并回归，不因格式改善提升等级。
- SCOUT: 调用 Skill Factory，寻找能解决 <任务> 的 GitHub 项目，先验证许可、依赖和成本，不批量制造产品。

调用者可覆盖低风险偏好，不能用省时理由静默削弱锁定标准。以技能目录定位脚本；在新工作目录存放子项目。启动先看标准，按需读手册。独立模型、盲评、封存和目标宿主均需真实环境，不能用本地脚本自测冒充。

续作：在工作目录保存状态模板。每次读回产品和报告、核对输入/代码/依赖是否变化；发生变化重跑相关测试。保存旧版、改动原因和恢复路径。产品问题只有证明具有跨产品普遍性，才提出母工厂改进；先自测/回归，再经授权升级母 Skill。

交付物：子 Skill ZIP（有实际本地候选证据时）、开发项目 ZIP、来源与许可证、测试原始证据、效果案例、运行条件、成本、安全和未完成项。草案明确标 E0；本地候选 E1；独立模型实测 E2；目标宿主 E3；客户实付 E4。等级按原标准，不跳级；实际商业审核和支付需另验。
