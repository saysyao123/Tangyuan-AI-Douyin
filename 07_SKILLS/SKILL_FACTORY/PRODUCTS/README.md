## 维护规范

- 每个产品使用永久唯一编号 SF-Pxxx；升级保留编号，新增版本记录，不覆盖旧证据。
- 每次 BUILD / AUDIT / EVOLVE 完成或中断后，更新 REGISTRY.json、对应产品档案及本页总览；SCOUT 仅在用户决定立项时登记。
- 开发状态与商业状态分开。开发：planned / developing / local_tested_candidate / release_eligible / archived。商业：not_released / submitted / listed / paid_verified / withdrawn。缺失证据用 unknown 或 not_run，不能写作通过。
- 沿用锁定标准 E0 结构检查、E1 试运行、E2 真实任务对照、E3 目标宿主独立运行、E4 真实客户付费/到账。E3 不自动等于商业合格；发布门槛以稳定版标准为准。
- 每次更新记录测试日期、模型/宿主、版本、输入范围、实际结果、限制、证据位置与下一步。旧版结果不得自动继承给新版本。
- 将失败及用户反馈归因：产品个别缺陷修复子 Skill，共性缺陷提交母工厂优化建议，验证后才升级稳定版。
- 本目录在公开仓库：只记录允许公开的元数据和脱敏证据；商业商品源码、封存题及答案、客户资料、密钥、订单明细不得默认上传。产品包可单独保存并记录位置与 SHA-256。不得擅自上架。

机器可读索引：[REGISTRY.json](REGISTRY.json)；新产品使用 [TEMPLATE.md](TEMPLATE.md)。
