# Round 01｜MV 黄金样板校准章程 v1.0

> 状态：LOCKED
> 目的：先把正确的 AI MV 生产流程、审美标准、Gate、返工逻辑和 Golden Sample 校准出来；R1 不以 1 小时和全自动化为通过条件。

## 1. R1 核心目标

从热门 BGM 发现开始，完整跑通一条高质量 AI MV 的正确生产路径，并把每一个关键阶段校准到足够可靠。

R1 完成时必须得到：
- 1 条用户认可的完整 MV 成片；
- 完整阶段记录；
- 成功与失败样本及归因；
- 人工介入与耗时记录；
- Golden Sample；
- 各关键阶段 Golden Reference；
- `MV SOP v1`；
- 待验证内容进入 `EXPERIMENTS`，不得伪装成稳定规则。

是否发布抖音不作为 R1 必须通过条件。若发布，由用户回传真实平台数据，作为后续表现验证。

## 2. 第一套视觉体系

第一套 Golden 视觉体系固定为：

**新东方电影感 + 写实电影底层 + 适度诗意超现实。**

长期识别核心不是固定人物长相，而是：

> 这套 MV 很会把歌词变成漂亮、准确、有记忆点的画面。

优先级：
1. 美感 / 漂亮；
2. 歌词视觉命中；
3. 导演层次与动态表现；
4. 人物表演。

不以完整叙事为第一目标。允许人物、环境、物件、光影、天气、倒影、空镜和适度超现实共同承担歌词表达。

## 3. 导演核心规则

- 技术正确只是底线；动态后明显比首帧丑，判 FAIL。
- 每句歌词先寻找“最美、最准、最值得记住的视觉答案”。
- 一句歌词允许自然拆为 2–3 个情绪 / 动作 Beat。
- 不设置机械景别配额；景别必须服从歌词与音乐。
- 判断导演是否模板化，核心看“视觉事件是否重复”，而非只看景别是否不同。
- 能把字面拍得漂亮就直接拍；字面太普通时可升级为情绪、隐喻和象征。
- 隐喻目标：第一眼觉得美，第二眼能品出歌词意思。
- 整体必须有强弱、留白和高潮，不能每秒都用力。

### 导演重复度 Gate｜HARD GATE

整组进入生成前必须检查：
- 是否连续慢推 / 慢拉；
- 人物是否总在站立、回头、抬手；
- 环境是否总是风吹、雨落、雾飘；
- 多镜头切换方式是否高度雷同；
- 核心视觉事件和运动方式是否重复。

重复度明显过高时禁止进入 Seedance，必须先局部重写。

## 4. 热门 BGM 与热门截取模板

R1 严格从最近 7 天热门 BGM 发现开始。

每次提供 5 首强候选：
- 4 首：热度高 + MV 类互动表现好 + 视觉适配高；
- 1 首：热度特别高、但与当前视觉体系不完全匹配的挑战候选。

歌曲范围：中文歌为主，普通话优先，粤语等中文歌曲可进入候选。

同一首歌存在原版、加速版、DJ、翻唱、现场等版本时，允许比较不同版本，最终按以下因素综合判断：
1. 同 BGM 的 MV 类视频点赞 / 互动表现；
2. 最近 7 天增长趋势；
3. BGM 使用热度；
4. 与当前新东方视觉体系的适配度；
5. 成片美感成功率。

若热度差距不大，优先选择更容易做出漂亮成片的一首 / 一个版本。

### 热门截取模板｜HARD REQUIREMENT

必须先研究同 BGM 当前 MV 类热门视频的主流截取区间：
- 常见开始位置；
- 常见结束位置；
- 常见长度；
- 主流截取模板；
- 多模板之间的互动表现差异。

R1 优先沿用主流热门截取区间，不为了 Hook 随意重新切歌，避免段落半截、语义断裂和热门片段错位。

若存在两个主流模板：优先看相关 MV 的互动表现；差距不大时，选择更适合当前视觉体系的一版。

## 5. BGM 可用性 Gate

第三方榜单 / 数据平台 / 公开信息可用于发现热歌，但最终候选必须回到抖音复核：
1. 抖音可搜索到；
2. 最近 7 天仍有新视频正常使用；
3. 用户自己的抖音账号可以直接选择并进入发布流程。

三层通过才标记 `BGM_AVAILABLE` 并进入正式制作。

Round 01 第 3 层由用户做一次轻量人工确认。

## 6. 热门 MV 参考分析｜FIXED STAGE

BGM 选定后、正式导演设计前，必须分析同 BGM / 同类热门 MV。

常规观察约 5–10 条，但以“已经看出稳定规律和明显同质化边界”为停止条件，不机械凑数量。

分析优先级：
1. 传播表现；
2. 纯审美；
3. 导演与剪辑；
4. 歌词表达。

传播层第一指标：**前 1–3 秒留人能力。**

目标不是照抄，而是建立市场侧审美、Hook、导演、剪辑和传播基准，并识别应该规避的同质化套路。

## 7. Opening Hook Gate｜HARD GATE

开头 1–3 秒必须单独验收。

逻辑：
> 第一帧先靠强美感停住人 → 前 1–3 秒发生明确视觉事件 → 热门歌词继续承接。

R1 不随意修改主流热门截取起点。Opening Hook Gate 解决的是：在不破坏热门截取模板的前提下，如何让第一帧和前 1–3 秒更抓人。

Gate 必须能回答：
- 第一帧为什么能停住人；
- 前 1 秒发生什么；
- 第 2–3 秒发生什么；
- 对应哪句歌词 / 哪个音乐节点；
- 为什么观众会愿意继续看。

## 8. 音乐结构与 Beat

正式分镜前必须先建立：
- 音乐结构；
- 歌词结构；
- 情绪变化；
- 初步 Beat 切分建议。

整体情绪曲线以音乐旋律、节奏、鼓点、强弱和高潮变化为主，歌词语义负责校正。

Beat 必须先按音乐、歌词、情绪自然切分，不能为了 5 秒生成单元硬切。

当自然 Beat 与 5 秒生产约束冲突：先保 Beat 完整，再在生产层适配；只有确实无法稳定实现时才拆 Beat。

Beat 与首帧不强制一一对应。视觉答案不同，即使只有 1–2 秒也可以独立首帧；同一空间、同一核心视觉事件可共用视觉单元。

## 9. 首帧系统

核心生产逻辑：**先首帧 → 再图生视频。**

首帧模型固定为 GPT；R1 不比较其他生图模型。

### 首帧定义：0 秒动态锚点

首帧必须同时锁住：
- 美感与构图；
- 光影与材质；
- 人物 / 环境关系；
- 核心视觉事件起点；
- 人物动作入口；
- 摄影机运动入口；
- 环境动态；
- 后续物理余韵。

首帧不是漂亮静态图，而是下一秒天然能动起来的设计。

### 首帧审核

先整组生成，再整体审片。

顺序：
1. 单张美感；
2. 整组导演层次；
3. 视觉事件与镜头语法重复度；
4. 世界、色彩、材质、光影统一；
5. 动态可执行性。

明显不漂亮的单张先淘汰，再谈整组统一。

## 10. 动态可执行性 Gate｜HARD GATE

首帧整组通过后，不可直接进入 Seedance。

必须额外检查：
- 动作入口是否清楚；
- 5 秒核心事件是否可实现；
- 摄影机运动是否可执行；
- 环境动态是否合理；
- Seedance 2 mini 成功概率；
- 是否容易在动态后损失首帧美感。

静态很美但明显不适合运动的首帧，必须在这里提前返工。

## 11. 人物与遮面硬规则

### 面纱 / 面罩机制｜HARD RULE

女性面纱、男性面罩机制固定保留，用于降低明显人脸带来的视频生成限制并形成视觉识别。

跨歌曲可调整：
- 发型；
- 服装；
- 面纱 / 面罩形式；
- 颜色；
- 材质；
- 具体人物气质。

固定的是遮面机制，而不是一成不变的服装和长相。

角色数量默认最多双主角。能单人表达就优先单人；需要关系感时再双人。

### 首帧人物封闭原则｜HARD RULE

每个 5 秒动态段里，只允许出现首帧中已经存在的人物。

禁止动态过程中新增人物、走入、从背景出现、路过、只露局部或以任何形式临时生成。

剧情需要新增角色时，必须从下一段新的首帧开始。

## 12. Seedance 动态规则

动态模型固定为 Seedance 2 mini；R1 不做多视频模型比较。

默认 5 秒一个生产单元，优先稳定与可控。

- 普通 Beat：优先一镜到底；
- 关键 Beat / 高潮：允许 3–5 镜；
- 多镜头默认先尝试让 Seedance 在一个 5 秒段内完成；
- 若模型不稳定，降级为多个简单动态素材再由后期组合。

每个 5 秒默认只有 1 个核心视觉事件；高潮可以在主事件下叠加少量辅助动态。

完整 5 秒都要设计，即使成片只使用 2–3 秒。

必须标出粗粒度有效区间，例如：
- 0–1.5s 建立；
- 1.5–3.5s 核心事件；
- 3.5–5s 余韵。

不要求精确到 0.1 秒。

不同视觉空间的短 Beat 默认分别生成各自稳定素材，再在剪辑阶段截取组合；只有同空间、同动作逻辑、同情绪时才优先合并在一个 5 秒生成段。

## 13. 动态提示词整组审核

通过动态可执行性 Gate 后，一次性生成整组动态提示词，再从整支 MV 角度审核。

检查：
- 运镜是否重复；
- 人物动作是否重复；
- 环境动态是否重复；
- 多镜头切镜逻辑是否重复；
- 强弱层次是否合理；
- 关键 Beat 是否真的更强；
- 普通 Beat 是否足够克制。

导演重复度 Gate 通过后才能进入 Seedance。

## 14. 动态 QA 与返工

### 单段 QA

直接 FAIL 的情况包括但不限于：
- 新增人物；
- 面纱 / 面罩失效；
- 人物漂移；
- 穿模 / 肢体异常；
- 动作错误；
- 核心事件未发生；
- 运镜失控；
- 风格漂移；
- 构图明显变差；
- 动态后明显损失首帧美感。

### 整组 QA

所有单段过关后，再整体检查：
- 导演层次；
- 动态重复；
- 强弱节奏；
- 整体美感；
- 高潮是否成立。

### 返工

先判断根因再决定返工层级：
- 动作 / 运镜 / 动态提示词问题 → 保留首帧重做动态；
- 首帧本身不适合运动 → 退回首帧。

同一方案连续失败两次：先降级动作、运镜和镜头复杂度；仍失败则换视觉方案，不死磕。

返工根因尽量定位到：
- 模型随机性；
- 动态提示词；
- 首帧；
- 导演方案；
- 上游流程 Gate。

多原因允许并列，但必须区分根因与次要原因。

## 15. 剪辑

正式剪辑前必须产出“剪辑时间线草案”，至少明确：
- 每个 Beat 对应哪个素材；
- 最终截取区间；
- 切镜位置；
- 音乐转折；
- 关键卡点；
- 自然 / 设计型转场；
- 余韵；
- 歌词出现 / 消失时间。

R1 的剪辑时间线是人工确认 Gate：用户确认后才进入自动剪辑。

剪辑原则：情绪流动 > 机械卡点。关键鼓点、歌词转折和高潮点再明显卡点。

转场以内容、运动方向、构图和光影的自然衔接为主；只有歌词或音乐明显转折时，少量使用设计型转场。

## 16. 基础歌词系统

歌词必须有。

R1 先只做稳定基础歌词系统，不做复杂歌词特效。等画面和导演系统稳定后，再单独开歌词特效校准。

基础方向：
- 现代无衬线为主，保留一点东方审美；
- 白字；
- 紧贴文字的半透明暗色圆角底；
- 最多 2 行；
- 根据语义、节奏、可读性自动断句；
- 默认固定字号，特别长句只允许小幅缩小；
- 位于抖音手机端安全、舒适的观看区域；
- 基本位置固定，可根据主体小范围上下调整；
- 第一轮只做轻微淡入淡出。

### 字幕居中｜HARD RULE

文字必须在底框内上下、左右视觉居中。

偏上、偏下、左右不均、框大字小、字贴边，全部判不通过。

后续稳定后再测试：局部渐变暗化、轻微上浮 / 下沉、关键句歌词特效。

## 17. 音频与歌词同步

最终以抖音可用热门原始 BGM 为主。

Seedance 生成视频自带声音默认全部删除。只有极少数明确提升电影感的镜头，才允许轻量加入环境声。

歌词同步：
- 句级同步是底线；
- 关键字 / 高潮词做词级同步。

歌词获取与校对也是正式流程：
1. 系统获取准确歌词；
2. 对照实际 BGM 版本；
3. 多来源交叉核对；
4. 用音频校正逐句时间码；
5. 仍有冲突时退回 ASR / 听写校准。

## 18. R1 阶段颗粒度

采用“阶段少、内部动作细、LOCK 点少而关键”的原则。

R1 预计约 8–12 个核心阶段，不为了管理而拆成二三十个小步骤。

若真实测试发现某阶段内部经常返工、问题类型明显不同或确实需要独立回滚，再根据结果拆分。

## 19. GitHub 与本地素材

GitHub 是唯一事实源、规则中心、项目状态中心。

大视频 / 大素材主要保存在用户本地电脑。

GitHub 与本地目录必须尽量一一对应：
`测试轮次 → 单首歌曲项目 → 阶段 / 素材类型`

GitHub 至少记录：
- 文件名；
- 项目与阶段；
- 本地相对路径；
- 对应提示词；
- 版本；
- PASS / FAIL；
- 淘汰原因；
- 最终采用关系。

每首歌曲项目必须有唯一 `CURRENT_STATE.md`，新 Agent / Codex / 新聊天进入项目时先读状态入口，不扫描全部历史。

Current State 使用中等详细颗粒度，至少说明：
- 当前阶段；
- 上一 LOCK 阶段；
- 当前有效版本；
- 关键结论；
- 风险；
- 待确认项；
- 下一步只能做什么。

## 20. 阶段提交与 LOCK

R1 采用两步式 Git 锚点：

1. 阶段产物完成 + AI 自检通过 → 提交阶段产物 Commit → 状态 `READY_FOR_REVIEW`；
2. 用户确认 PASS → 单独做 LOCK Commit，同时更新 Current State，正式进入下一阶段。

后续某阶段经过多轮验证稳定后，可以升级为自动验收 / 自动 LOCK / 自动继续。

若自动阶段出现以下任一情况，自动降级回人工 Review：
- 严重质量问题；
- 重复性错误；
- 明显低于 Golden Reference；
- 返工率突然升高。

默认只降级出问题的阶段；只有会污染上下游的系统性问题才扩大降级范围。

自动升级门槛不在 R1 预设数字，R1/R2 根据真实结果再定。

## 21. AI 自检｜HARD RULE

任何阶段产物进入人工 Review 前，必须先通过 AI 自检 Gate。

流程：
`阶段产物 → AI 自检 → 自动修正 → AI 自检通过 → READY_FOR_REVIEW → 用户确认`

AI 自检连续两次失败后必须做根因分析：
- 可自动修复 → 允许最后一次自动修正；
- 审美不确定 / 规则冲突 / 上游设计错误 / 需要人类判断 → 直接升级人工 Review。

### AI 自检漏检｜HARD RULE / 重点复盘

如果 AI 自检 PASS，但用户人工 Review 判 FAIL，必须标记 `AI_SELF_CHECK_MISS`。

记录：
- AI 当时为什么判断通过；
- 用户为什么否决；
- 缺失的是规则、评分标准还是案例；
- 能否转成新的自检标准。

根据问题类型沉淀为：硬规则 / Checklist / 评分标准 / 成功失败对照样本，不强行都变成硬规则。

## 22. 成功与失败样本｜HARD RULE

失败样本必须归档，且必须真实、原始、可追溯。禁止为了未来账号内容重新“演”一个失败。

失败至少记录：
- 原始结果；
- 原始提示词；
- 固定失败标签；
- 自由说明；
- 根因 / 次要原因；
- 修复方法；
- 对应 Commit；
- 修复后结果；
- 回滚锚点。

成功样本同样必须结构化归因：
- 为什么构图成立；
- 为什么歌词命中；
- 哪个视觉事件有效；
- 哪种动态设计稳定；
- 哪类提示词表达值得复用。

## 23. 人工介入与耗时记录

R1/R2 都必须记录人工介入，且关联到阶段、产物 / 失败样本、修改动作、Commit、修复结果和回滚点。

人工介入至少记录：
- 必须确认；
- 审美判断；
- 技术故障；
- 流程缺陷；
- 人工救火；
- 介入原因；
- 修改内容；
- 优化方案；
- 结果。

R1 同时记录三类时间：
1. 总经过时间；
2. 用户实际人工操作时间；
3. AI / 模型等待时间。

AI / 模型等待时间进一步拆分：
- 正常生成等待；
- 失败返工等待。

每次返工等待记录返工根因，目标是在 R2 中尽量消除可避免返工。

R1 不以 1 小时为通过条件，只记录真实耗时与介入情况。

## 24. 内容证据库

R1/R2 的工程记录同时服务于未来正式账号内容素材。

证据素材保存优先级：
1. 失败过程；
2. 效率变化；
3. 前后对比；
4. 最终成果。

必须保留原始错误画面、错误提示词、当时反馈、修改记录、耗时变化、人工介入减少、最终效果对比，并可追溯到对应阶段和 Commit。

## 25. Golden Sample / Golden Reference

R1 最终 PASS 成片成为第一版 Golden Sample。

后续作品不机械复制画面，但不能明显低于它的：
- 单帧美感；
- 歌词视觉命中；
- 导演层次；
- 动态质量；
- 剪辑；
- 基础歌词完成度。

关键阶段也建立各自 Golden Reference，可独立升级，无需等待整条 MV 全面超越旧样本。

前几轮任何 Golden Reference 升级必须由用户确认；后续 AI 可提出升级建议，但最终替换仍保留人工确认。

## 26. 规则演进

旧项目、旧 SOP、过去成功与失败案例只作为参考证据库，不因“以前用过”自动成为 R1 有效规则。

用户最新明确反馈优先作用于当前项目；若与现有规则冲突，先记录为 Rule Change Candidate，在当前项目验证确实更好后再正式升级 Golden Reference / 替换旧规则。

正式规则区只保留当前有效版本；被替代规则移入历史 / Deprecated 区，记录：
- 为什么被替代；
- 新规则是谁；
- 从哪个项目 / Commit 起失效。

R1 验证有效的内容可以进入 `MV SOP v1`，但必须标注验证强度；R2 再通过多歌曲复测决定哪些规则真正升格为稳定规则。

## 27. R2 预设验证目标

R2 再验证自动化与效率，不属于 R1 通过条件。

R2 样本：10 首歌：
- 7 首常规适配型；
- 3 首不同类型挑战型，覆盖不同边界。

暂定质量目标：
- 首轮直接达标 ≥ 6/10；
- 返工 1 次后 ≥ 9/10；
- 返工 2 次后 10/10。

R2 开始正式验证：
- 全链路逐步接近 1 小时；
- 10 首歌整体平均，每首全流程人工介入 < 2 次；
- 成片不明显低于 Golden Sample；
- 自动阶段失败时可按 Gate 机制降级回人工 Review。

R2 达标后，再迁移经验到正式抖音账号的低成本工作日轻量更新系统。

## 28. Non-Goals｜R1 明确不做

R1 不做：
- 不以 1 小时完成为验收；
- 不追求完整全自动；
- 不比较多个视频模型；
- Seedance 2 mini 固定；
- GPT 首帧生图固定；
- 不追求多套视觉体系；
- 不做复杂歌词特效；
- 不做多账号运营；
- 不把爆款作为 R1 验收；
- 不把变现作为 R1 验收；
- 不提前抽象成所有视频通用的超级系统；
- 不一次性重构整个 GitHub；
- 不为了自动化牺牲美感；
- 不因为旧 SOP 存在就默认其正确。

## 29. R1 完成定义

R1 只有在以下条件同时满足时结束：

`热门 BGM 筛选 → 抖音可用性确认 → 热门 MV 参考分析 → 歌词/音乐结构 → Beat → Opening Hook → 导演方案 → 首帧组 → 动态可执行性 Gate → 动态提示词与导演重复度 Gate → Seedance 动态生成 → 单段/整组 QA → 剪辑时间线 → 基础歌词 → 最终成片 QA`

全部跑通，并且：
- 用户认可完整成片；
- 阶段记录、反馈、成功/失败原因已归档；
- Current State 与 Git 状态一致；
- Golden Sample / Golden Reference 已建立；
- `MV SOP v1` 已整理；
- 待验证假设已与正式规则分离。

发布属于可选的后续平台验证，不影响 R1 制作系统是否完成。
