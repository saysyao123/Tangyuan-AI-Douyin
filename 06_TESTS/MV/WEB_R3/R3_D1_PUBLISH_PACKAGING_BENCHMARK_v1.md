# 3. Candidate A｜MUSIC_FIRST

## Position
Search/recognition first.
The viewer should know the song immediately, then receive one emotional reason to stay.

### COVER_FRAME
Preferred: `S01` eye/veil/wind close-up.
Reason:
- strongest 0-second recognition;
- human gaze stops scroll better than a generic sky/landscape frame;
- visually distinct from competitor star-sky packaging.

Fallback: `S08` world-opening final frame if cover grid needs a brighter overall profile.

### COVER_TEXT
Primary:
`如果风会替我说话`

Small secondary line only if layout remains clean:
`有些话，就让风替我说`

Rules:
- no `AI生成` as main cover identity;
- no long sentence;
- no hashtag on cover;
- no decorative English.

### POST_TITLE
`如果风会替我说话｜有些话没说出口，就让风替我说吧`

### POST_DESCRIPTION
`有些牵挂，不一定真的要说出口。`

`这次把《如果风会替我说话》做成了一段雨夜到天亮的治愈画面：风替她开口，雨替她回答，最后把没有说完的话留在天亮以后。`

`戴耳机听，会更完整。`

### HASHTAGS
`#如果风会替我说话 #音乐推荐 #治愈系 #氛围感 #AI视觉`

Tag order rationale:
1. exact song search;
2. music-category identity;
3. healing-format identity;
4. mood discovery;
5. AI as production attribute, not primary content identity.

### PINNED_COMMENT
`这段里你最喜欢哪一句？我最想留下的是最后那句。`

Purpose:
- lyric-based low-friction comment entry;
- does not beg for follows;
- creates a clear response target.

### Expected strength
- strongest search clarity;
- cleanest attribution to song interest;
- lowest packaging ambiguity;
- best first R3-D baseline because it is easiest to interpret after publishing.

### Risk
- emotional hook is slightly less aggressive;
- may look more like conventional music recommendation packaging.

# 4. Candidate B｜EMOTION_FIRST

## Position
Emotion first, song identity second.
The viewer is first pulled by an unsaid-feeling sentence, then sees the song name.

### COVER_FRAME
Preferred: `S08` world-opening release frame.
Reason:
- visually carries healing rather than sadness;
- creates contrast against rainy-night body of video;
- differentiates the cover from conventional face-close music posts.

Alternate: S01 if feed tests show distant figures lose too much thumbnail impact.

### COVER_TEXT
Primary:
`没说出口的话`

Secondary:
`风会替你说吗？`

Keep song name in title/caption rather than adding a third cover line.

### POST_TITLE
`没说出口的话，风真的会替你说吗？｜如果风会替我说话`

### POST_DESCRIPTION
`如果有些话已经来不及说，就别再逼自己一定要得到回答。`

`风吹过去，雨停下来，天总会慢慢亮。`

`《如果风会替我说话》这一段，我更想做的不是“伤感”，而是那种还会想起，却已经能继续往前走的感觉。`

### HASHTAGS
`#如果风会替我说话 #氛围感 #治愈系 #音乐推荐 #AI视觉`

### PINNED_COMMENT
`如果风真的能替你说一句话，你最想让它替你说什么？`

Purpose:
- stronger emotional self-projection;
- potentially higher comment depth;
- natural UGC-style participation prompt.

### Expected strength
- stronger emotional hook;
- more differentiated from standard song-promo captions;
- pinned comment may generate richer responses.

### Risk
- song recognition arrives later;
- title is longer;
- performance attribution becomes less clean: if it works, it may be emotion-copy rather than song/search strength.

# 5. Controlled-test recommendation

For the **first real R3-D publish**, recommend:

`SELECT = MUSIC_FIRST`

Reason:
R3-A's new variable was Music Radar. The cleanest first live-data test should preserve clear song identity so we can later ask:
`Did a radar-selected, exact-version-locked song + improved visual system actually work?`

If EMOTION_FIRST is used first, strong/weak performance becomes harder to attribute because the packaging hook itself introduces a larger emotional-copy variable.

Therefore:
- publish MUSIC_FIRST once;
- store EMOTION_FIRST as a counterfactual candidate;
- do not repost the same video with B;
- use B as the active direction on a later different MV if we want a real cross-video packaging comparison.

This follows the R3 Master Plan rule:
`one actual publish, one recorded alternate; no duplicate-video A/B`.
