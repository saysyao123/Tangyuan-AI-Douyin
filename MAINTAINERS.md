# Maintainers

## Primary maintainer

- **saysyao123** — repository owner and primary maintainer

Primary maintainer responsibilities currently include:

- production-runtime architecture and rule ownership;
- issue triage and failure classification;
- experiment design and evidence review;
- cross-song regression decisions;
- promotion of experimental knowledge into authoritative rules;
- repository hygiene and secret/privacy controls;
- release planning and documentation alignment;
- review of changes that affect Human Gates, state transitions, timing truth, or production rollback boundaries.

## Maintainer model

The project is currently maintained primarily by the repository owner while contributor workflows are being opened and documented.

As the project grows, maintainer responsibilities may be split by subsystem, for example:

- audio identity / timeline;
- director and camera runtime;
- first-frame / image-to-video QA;
- source normalization / editing;
- state, CI and maintenance automation;
- documentation and public fixtures.

Maintainer decisions should be evidence-based. A new technique should not become an authoritative production rule solely because it produced one successful output.
