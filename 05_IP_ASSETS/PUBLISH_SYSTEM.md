# PUBLISH_SYSTEM v1.0

> 目标：建立30天统一但不僵化的发布包装。

## 1. 系列封面骨架

固定：

- 左上：`汤圆AI实战`
- 右上：`DAY XX`
- 中央：本期唯一冲突 / 结果
- 底部：`30天AI账号实验｜37→1000`

变化：

只变化中央本期主题。

Day1：

> 做了这么多视频  
> 为什么才37粉？

## 2. 标题规则

标题把最宝贵的位置留给：

**本期冲突 + 认知发现**

不建议固定从：
`Day XX｜...`
开始。

DAY编号由封面承担。

Day1确认版：

> 做了这么多视频，我终于知道为什么只有37粉

## 3. 简介结构

固定三段：

1. 真实背景/问题
2. 本期核心发现
3. 连续实验与下一集理由

避免：
- 求关注
- 夸张成功承诺
- 假装已经跑通

## 4. 标签结构

不固定每天同样的标签文字。

固定结构：

1. 目标人群
2. 内容赛道
3. 本期精准关键词
4. 次级赛道 / 当前高度相关话题

Day1确认版：

`#普通人学AI #自媒体运营 #账号定位 #短视频运营`

品牌系列感由：
- 账号名
- 封面
- DAY
- 37→1000

承担，不需要每次浪费标签位做自创品牌话题。

## 5. BGM

发布前不再临时花大量时间找音乐。

默认声音家族：

- 无歌词
- 轻科技纪录片感
- 克制
- 不抢真人声音

建议建立3类预设：
- Review：复盘/踩坑
- Method：教程/方法
- Result：结果/实验

声音主体永远是真人旁白。

BGM只做底色。

## 6. 发布数据

发布后固定记录：
- 1h
- 3h
- 24h

封面/标题/标签是否有效属于性能实验，不能因个人审美直接锁为增长规律。
