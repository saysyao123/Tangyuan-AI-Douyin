# 0｜视觉系统总公式

```text
BACKGROUND ENVIRONMENT
    ↓
STRUCTURE / PATH
    ↓
IP ASSET OBJECTS
    ↓
REAL EVIDENCE
    ↓
TYPOGRAPHY / SUBTITLE
```

五层职责严格分开：

- Background：空间、气质、景深、统一感
- Structure：顺序、因果、路径、连接、状态变化
- IP Assets：提高识别度、材质感、完成度
- Evidence：证明事情真实发生
- Typography/Subtitles：准确语言与关键结论

任何一层都不能越权：

- 背景不能产生新的叙事信息
- 生图资产不能承担准确文字、数字、证据
- HyperFrames 不重画真实证据冒充原始现场
- 字幕不重复程序化画面的全部信息

# 2｜账号签名视觉：Tangyuan Node

## 2.1 Tangyuan Node 是什么

一个非常克制的“圆形核心节点”：

- 基础为暖黄圆点 / 圆环
- 颜色默认 `#FFD54A`
- 周围可有一圈极细暖白或深绿描边
- 不做卡通汤圆
- 不画表情
- 不拟人

它是“汤圆”名字的抽象视觉签名，而不是吉祥物。

## 2.2 它可以承担的角色

- 当前流程的 Active Node
- 一个规则被确认后的 Stamp
- 一条路径真正接通时的 Flow Token
- 关键结论出现前的 Voltage Moment
- Opening / Closing 的小型识别符

## 2.3 使用纪律

一帧最多一个真正的 Tangyuan Voltage Moment。

禁止：
- 每个节点都做黄圆
- 满屏黄色
- 每个转场都滚一个圆
- 把圆点当无意义装饰

原则：

> **圆点只有在“当前逻辑真正发生变化”时才亮。**

# 4｜Typography

## 中文主字体

- Noto Sans CJK / 思源黑体类
- 正文：Medium
- Hero：Bold / Heavy（按环境可用字体）

## 技术索引 / 英文 / 数字

- JetBrains Mono 或同类等宽字体

## 字体角色

### Hero
- 结论
- 一个关键词
- 一个数字
- 不写长句

### Body
- 只补足画面关系
- 不抄完整口播

### Mono
- 文件名
- 状态
- Step
- QA
- Rule
- Technical Index

## 视觉层级

Hero 与第二层信息至少通过两种方式拉开：
- Size
- Weight
- Contrast
- Position
- Motion order

# 5｜Shape Language

## 基础形态

- 常规面：12–18px 圆角
- 大型Artifact：20–26px 圆角
- Pill：只用于状态/Tag
- Full Circle：尽量只留给 Tangyuan Node / 状态点
- Hairline：1–2px

## 阴影

只允许一套克制阴影：

- 低不透明度
- 宽扩散
- 不做重黑投影
- 不做霓虹Glow包围所有元素

## 重要规则

**不同信息必须拥有不同视觉身份。**

- Prompt / 文档 → document artifact
- Audio → waveform / audio object
- AI核心 → anchor core
- 流程 → path / connector
- Rule → patch / stamped module
- QA → scanner / checklist / status strip
- Output → video artifact / result surface
- Evidence → real screenshot stage
- Conclusion → typography

禁止“万物皆圆角卡片”。

# 6｜Background System

背景是独立的 Motion Environment，不是颜色填充。

## BG01｜Deep Silk

**默认解释背景**

适用：
- AI工作流
- Prompt
- Agent
- Codex
- 方法论
- 普通知识解释

视觉：
- 深墨绿色连续柔性纹理
- 运动非常慢
- 类 Silk / soft flow
- 轻颗粒
- 轻暗角

强度：LOW

原则：
> 认真看才发现背景在动。

## BG02｜Logic Field

适用：
- 顺序
- 因果
- 工作流
- 循环
- 系统

视觉：
- 深色空间
- 远处只有少量极弱纵向/斜向轨道线
- 偶尔有非常慢的微弱数据光
- 前景真正流程线始终更亮、更具体

强度：LOW–MEDIUM

---

## BG03｜Evidence Stage

适用：
- 真实截图
- Prompt
- QA记录
- 数据
- Day1视频
- Before / After

视觉：
- 接近深墨绿摄影棚
- 极弱环境渐变
- Grain
- Vignette
- 一处弱暖光

强度：VERY LOW

原则：
> Evidence 是绝对主角。

---

## BG04｜Concept Light

适用：
- Rule Injection
- “工作流有记性”
- “修下一次起点”
- 认知峰值

视觉：
- Deep Silk / Logic Field 基础
- 加一条克制暖金 Light Ray
- 或局部更明显材质变化

强度：MEDIUM

只用于高潮，不连续使用。

---

## BG05｜Cinematic Plate

来源：AI生图高质量 9:16 Background Plate。

要求：
- 无人物
- 无文字
- 无Logo
- 无真实数据
- 中央/主要信息区留负空间
- 深墨绿 + 少量暖金
- 可分前/中/后景

HyperFrames再添加：
- 1.00→1.02/1.03极慢Push
- 前后景轻Parallax
- Light shift
- Grain

适用：
- 高价值Explanation
- AI电影镜头与程序化镜头之间的风格桥

# 7｜IP Asset Architecture

## Layer A｜Core Anchors

### TY-CORE-01 Tangyuan Node
品牌核心圆点。

### TY-CORE-02 AI Core
一个稳定、克制的AI处理核心。
不是机器人脑袋，不是OpenAI Logo，不使用具体品牌。

### TY-CORE-03 Human Control Point
代表“人”的输入/验收位置。
优先用真实手、Cursor、Check动作，不做头像。

---

## Layer B｜Input Objects

### Prompt Artifact
纸张/数字文档混合质感，暖白或墨绿色。

### Audio Object
波形、录音胶囊、声音纹理。

### Source Image
高清Source视觉框。

### Motion Clip
带轻时间线/播放状态的视频对象。

### Old Draft
旧稿对象，视觉上比当前真实输入更“旧/纸张化”。

---

## Layer C｜Process Objects

### Path / Connector
程序化SVG/Canvas绘制。

### Rule Patch
“规则进入系统”的实体对象。

### QA Scanner
检查/探测，不直接假装真实软件界面。

### Queue / Stack
任务排队、错误积累。

### Gate
验收节点。

---

## Layer D｜Status Objects

- Error
- Warning
- Pass
- Locked
- Draft
- Real Evidence
- Programmatic Explanation

状态优先小而清楚，不抢Hero。

---

## Layer E｜Output Artifacts

- Final Video
- Transcript
- Rule Update
- Correct Result
- Next Task

结果必须拥有和输入不同的视觉身份。

- 准确文字
- 数字

- Dark editorial tech

# 9｜Motion Identity｜Tangyuan Motion Grammar v1

IP感不只来自“长什么样”，更来自“怎么动”。

## 核心Motion Verbs

- **Seat**：对象稳稳落位
- **Connect**：路径接通
- **Swap**：变量换位
- **Patch**：规则嵌入
- **Reveal**：证据/结果出现
- **Route**：任务改变路径
- **Lock**：验收通过后锁定
- **Stamp**：规则/状态被确认
- **Resolve**：最终停止，允许读图

## Timing Tiers

- Micro：0.16–0.24s
- Normal：0.32–0.55s
- Gravity：0.60–0.90s
- Cinematic / Background：1.2–6s

## Easing Personality

默认：
- Entrance：长尾减速，克制
- Reposition：平滑 inOut
- Exit：比Entrance快
- Error：可以更快、更硬
- Conclusion：慢下来并停住

禁止：
- 每个对象同速度
- 每个对象同方向
- 每次都Bounce
- 所有元素永久漂浮

# 10｜Signature Moves

每个复杂Explanation只选一个主Signature Move。

## 10.1 Fixed Anchor Swap

适用：
- “AI没换，顺序换了”

AI不动，变量换位。

## 10.2 Rule Patch

适用：
- “让工作流有记性”

Rule模块嵌入系统，下一任务自动走新路径。

## 10.3 Path Rewire

适用：
- 流程修正
- 错误→正确

旧路径断开，正确路径重新接通。

## 10.4 Camera Journey

适用：
- 原因→结果
- 从输入一路看到产出

摄影机移动本身必须解释因果，否则不移动。

## 10.5 Evidence Reveal

适用：
- 真实截图/QA/Prompt

程序化世界退后，真实Evidence进入Hero。

# 11｜Logic → Visual Recipe Router

| 逻辑 | 首选视觉语法 |
|---|---|
| 顺序变化 | Fixed Anchor + Variable Swap |
| 因果 | Path + Camera Journey |
| 错误→修正 | Path Rewire / Before-After Process |

| 真实证据 | Evidence Stage + Artifact Reveal |
| 单个结论 | Titlecard / Held Read |
| 数据趋势 | Count/Chart + One Hero Datum |

# 12｜9:16 Composition

- 原生 1080×1920 设计
- 禁止16:9先做后裁
- 主视觉占画面约40%–60%
- 关键结构优先纵向
- 一个主要场景最多2个主焦点
- 背景/中景/前景至少三层
- 不连续两段同构图
- 一条视频至少使用3种 framing

## Subtitle Safe Zone

现有字幕中心约：`Y = 1432`

重要Hero与关键路径尽量避开：

`Y ≈ 1320–1560`

字幕可以覆盖环境/低权重元素，但不能盖住逻辑主节点。

# 13｜Scene Energy

一条完整视频不要所有Explanation都同能量。

### LOW
Evidence / held read / conclusion

### MID
普通流程解释

### HIGH
关键换位 / Rule Patch /认知翻转

### PEAK
每条视频最多1–2个真正高潮HyperFrames段

背景强度必须跟随Scene Energy，而不是每段都最大。

# 14｜Anti-Template

即使使用同一个Asset Pack，也必须避免模板感。

保持不变：
- Palette family
- Tangyuan Node
- Typography roles
- Motion Grammar
- Shape language
- Evidence discipline

允许变化：
- 构图
- 背景Preset
- Hero object
- Signature Move
- 景别/Camera
- 信息密度

IP感来自“语法一致”，不是“每条视频同一张模板”。

# 16｜最终判断标准

任何一个 HyperFrames 镜头，按以下顺序验收：

1. **Logic Correct**：逻辑有没有错？
2. **One-glance Clarity**：静音看能不能大概理解？
3. **Narrative Sync**：旁白说到哪里，画面发展到哪里？
4. **IP Recognition**：是否属于Tangyuan系统，而不是第三方模板？
5. **Beauty**：层级、材质、空间、运动是否好看？
6. **Restraint**：有没有为了高级而多做？
7. **Determinism**：最终Render是否可Seek、稳定、可重复？

优先级永远是：

> **逻辑正确 > 看得懂 > 叙事同步 > IP感 > 美观 > 动画复杂度**
