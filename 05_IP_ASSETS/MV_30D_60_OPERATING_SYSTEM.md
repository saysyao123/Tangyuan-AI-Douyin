# MV 30D/60｜Operating System v1

> Status: `ACTIVE EXPERIMENT / ACCOUNT-LEVEL OPERATING PLAN`
> Horizon: next 30 days
> Output target: approximately 60 music-MV posts / ~2 per day
> Principle: scale the validated R3 production system without reproducing R3-level R&D cost on every single post.

---

# 1. Account experiment objective

For the next 30 days, the account's primary content identity becomes:

`music / lyric emotion`
+ `AI cinematic visual`
+ `healing / atmosphere`
+ `repeatable production system`.

This is no longer the previous `37 -> 1000 / general AI practical experiment` front-facing content season.
That previous phase remains historical evidence in `PROFILE_HISTORY.md`.

Current 30-day question:

> Can a repeatable AI music-MV pipeline produce enough quality and consistency at ~2 posts/day to build a clear audience expectation and generate useful performance evidence?

Do not promise 60 viral videos.
The target is 60 controlled production/publication samples.

# 3. Old-content handling

Default:
- do not mass-delete old posts;
- do not reopen old content production;
- let the next 7–10 days of high-frequency MV output rebuild the visible profile grid;
- unpin old posts only if they dominate the profile entry experience;
- after at least 12–18 new MV posts, review whether any old post still materially confuses audience expectation.

Reason:
60 new posts will quickly become the dominant account identity; mass hiding is not required before evidence exists that old content is hurting conversion.

# 4. 60-post portfolio｜Do NOT make all 60 the same production class

## Lane P｜Primary / Trend MV — 30 posts

Cadence: about 1/day.

Purpose:
- highest production-quality baseline;
- radar-selected or strong recent song;
- 20–30s typical duration;
- 6–8 lyric/visual beats when needed;
- use exact Douyin audio-asset discovery;
- use R2/R3 correctness pipeline;
- stable visual language + selective new director grammar.

Default packaging:
`MUSIC_FIRST`, unless a later live-data experiment explicitly changes one packaging variable.

## Lane S｜Stable / Fast MV — 24 posts

Cadence: about 6/week.

Purpose:
- preserve output volume without turning every post into a new R&D project;
- 15–22s typical duration;
- 4–6 visual beats;
- prefer proven stable shot grammar;
- avoid high-risk physics as hero event;
- use environment / light / wind / reflection / space rather than difficult liquid simulation;
- reuse R3 Knowledge only where it reduces risk.

These are not low-quality posts; they are lower-complexity posts.

## Lane R｜R&D MV — 6 posts

Cadence: ~1–2/week.

Purpose:
- systematically improve director / camera language;
- only one major experimental variable per video.

Example variables:
- Dolly-out amplitude;
- partial occlusion percentage;
- hidden occlusion transition;
- world-opening crane/retreat;
- rack-focus semantic transfer;
- mini arc/orbit under simple physics;
- shot-scale sequence design.

Do not test difficult physics and difficult camera movement in the same R&D source.

Total:
`30 + 24 + 6 = 60`.

# 5. Daily publishing model

Target average: 2 posts/day.

Recommended pairing:
- Slot A: `Lane P` main/trend MV;
- Slot B: `Lane S` on normal days or `Lane R` on R&D days.

Do not assume one universal best publishing hour before data exists.
Use two stable separated posting windows in the first week, record exact timestamps, then compare results.

Do not post the two daily videos back-to-back.

---

# 6. Batch Gates｜Preserve 5 Human Gates without creating 10 interruptions/day

The validated 5 Human Gates remain conceptually intact:
1. HG01 Song Aesthetic
2. HG02 BGM Excerpt Listening
3. HG03 First-frame / Visual Direction
4. HG04 Picture Rhythm
5. HG05 Final Acceptance

For 60-post scale, change the interaction unit, not the correctness standard.

Use batch review:
- HG01: review 7–14 song candidates in one batch;
- HG02: listen to multiple BGM excerpts in one batch session;
- HG03: review 2–4 first-frame sets per batch;
- HG04: review 2–4 clean Picture Edits per batch;
- HG05: review final candidates in small batches when production is stable.

Do not remove the underlying Gate state simply to increase throughput.

# 7. Weekly production cadence

## Weekly planning block

Maintain a queue of at least 14 publish-ready song candidates.

Recommended weekly inventory:
- 7–10 recent / radar / trend candidates;
- 4–6 evergreen / revival / strong lyric-visual-fit candidates;
- 1–2 R&D candidates chosen for camera-language testing.

Do not require every song to be a 3-account STRONG repeat; that would bottleneck 60-post volume.
Instead preserve evidence tiers and compare performance later.

This is a production hypothesis, not yet a promoted trend rule.

## Batch flow

`Song Queue`
→ batch HG01
→ exact/audio discovery
→ batch HG02
→ Audio Timeline Package
→ Director allocation
→ batch HG03
→ first-frame generation
→ dynamic source generation
→ Dynamic QA
→ WEB Source Rough-Cut Gate
→ batch HG04
→ subtitle/final implementation
→ batch HG05
→ publish queue
→ 1h / 3h / 24h data.

# 8. Dynamic-generation default for scale

Default priority:
`stability > physical spectacle > prompt complexity`.

Use the R3 Knowledge candidates as production heuristics:
- Weakest Sufficient Motion;
- First-frame State Preload;
- Static Base -> One Allowed Event;
- One Difficult Physics Event per Source;
- Control Budget;
- Surface Ownership;
- physically believable > visually loud;
- serialize physics and camera/focus when high-risk materials exist;
- rain defaults to atmosphere, not hero physics.

Important:
These remain Knowledge hypotheses until cross-song repetition proves them.

---

# 9. Camera-language development inside the 60-post sprint

Do not stop camera experimentation.
Separate it from normal production.

Create a rolling Camera Test Series where each R&D MV changes only one camera variable.

Current positive-evidence candidates from R3:
- mild Slow Dolly-out Reveal;
- partial Foreground Occlusion / Reveal;
- near-full Occlusion as motivated hidden edit point;
- Rack Focus object -> emotion;
- World-opening Crane / Retreat benchmark.

Unproven / needs isolated tests:
- exact glass-parallel slider;
- diagonal slider;
- mini orbit / arc amplitude;
- portrait micro-dolly accuracy.

Every test records:
- CAMERA_EXECUTION;
- IDENTITY_STABILITY;
- SPACE_TOPOLOGY;
- PHYSICAL_PLAUSIBILITY;
- LYRIC_FIT;
- EDITABILITY;
- CLEAN_ENDPOINT.

Only cross-song stable grammar is eligible for Camera Library promotion.

Recommended experiment blocks:

`follows_per_1000_views = new_follows / views * 1000`.

Secondary:
- like rate;
- favorite rate;
- share rate;
- comment rate;
- completion relative to video duration.

Do not promote a performance rule from one post.

# 12. Success criteria after 30 days

The 60-post sprint should answer:

### Production
- Can 2/day be sustained without visual-quality collapse?
- What is median production time by P/S/R lane?
- What percentage passes dynamics without regeneration?
- Which camera grammars repeat reliably?
- Which physical events should be removed from default production?

### Content
- Which song evidence tier performs best?
- Which visual motifs produce higher completion/favorite rates?
- Does MUSIC_FIRST remain best for search/recognition?
- Does EMOTION_FIRST improve comments/follows on selected songs?

### Account
- Does the profile acquire a clear music-MV audience expectation?
- Which posts drive profile visits and follows?
- Does 2/day improve learning rate without cannibalizing distribution?

At Day 30, perform a production + performance promotion audit before deciding whether to continue at 60/month, increase, reduce, or reposition again.
