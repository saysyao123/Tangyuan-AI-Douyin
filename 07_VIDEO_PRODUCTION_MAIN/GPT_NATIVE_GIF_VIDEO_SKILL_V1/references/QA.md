# 质量门禁 v1.1.0

质量顺序：源帧完整 → 固定镜头／无滚动 → 人物与动作合理 → 时间／编码／回读 → 完整播放。不能用最后的格式数字掩盖前面失败。

## 1. 源 GIF

- 真 GIF；顺序解码所有帧，记录逻辑画布、局部矩形、disposal、透明底色、逐帧时长、总时长、循环与 SHA。
- Pillow 负责 GIF87a/89a 及 disposal 后的全画布重建；确认本次解码结果与素材一致。透明区显式合成，不将隐藏 RGB 误作可见背景。
- 看全部源检查页，核对人物、手部、衣服和地标；拒绝滚动、错切、分屏、截断和突然变景。自动光流背景位移检查只覆盖有足够纹理的代表性负例，不能证明人物一致性。
- 单帧、全静止源、无／零时长、破损文件、超过 CPU 资源配置默认拒绝。不偷偷补一个任意 duration。
- `--source-reviewed` 由实际查看后的执行 Agent 使用。源不合格停止；不得依赖插帧修复源错误。

## 2. 时间与补间

- 使用每帧累计起始时间映射；24 FPS 采样点从 0 至 119/24 秒。GIF 最后帧时长是自然停留，不擅自循环或延伸新动作。
- 报告 `source_sample`／`interpolated`／`terminal_hold` 实际计数与逐帧映射。30 个源帧不必然在任意输出时基完整落点；不要做 120−30 的虚假统计。
- `flow_flagged_source_pairs`给出双端warp大连通分歧风险；历史16→17帧的手部重影能被本次规则提示。仍需实际查看，不能据无flag自动通过。
- 相邻光流每对只算一次双向场；warp 保留 V1 参数（包括 ±24 像素约束与近似反向采样）。这不处理所有遮挡，手指／头发／窗框交界逐帧审查。
- 静态背景 color pumping 可用共享色板减少；源本身的明暗漂移、重绘和摄影细节损失不能靠色板消除。
- GIF 真实停留允许保留同像素图像块，不更改像素来凑差异；重复帧数必须如实记录。末尾 3 帧自然 hold ≠ 3 个新动作。

## 3. 文件

- 目标 GIF89a，120 图像帧／5000ms，40/50ms 延时合计正确。输出默认不循环、全片色板、完整不透明帧，disposal=1。它不等同 CFR 24 FPS。
- MP4 实际解码 120 帧，`r_frame_rate` 与 `avg_frame_rate` 均 24/1，帧时间戳逐个核对，视频时长 5.000 秒，H.264／yuv420p、SAR 1、faststart。完整解码包括可选音轨，FFmpeg 解码出错必须失败。
- 奇数宽高右／下补最多 1 像素并报告；默认不缩放，不改变源比例。真实 9:16 fixture 单独验证，历史 144×328 源不是 9:16，不能拉伸冒充。
- 文件真实非空，来源、源码版本、运行环境、音频来源（如有）和输出 SHA 可核验。使用空输出目录，避免失败时旧成片冒充本次成功。
- 可选音频 AAC 检查轨道存在、时长在 50ms 内；只证明封装和截补，不证明音画语义、听感或口型同步。

## 4. 完整视觉验收

- 技术脚本只能写 `TECH_PASS_VISUAL_PENDING`。
- 完整播放 MP4；看全部源帧及输出帧，重点逐帧检查抬手、眨眼、接触／遮挡、末尾动作和首尾跳变。16 格仅作预览，不等于完整检查。
- 单独保存视觉记录：审核者、文件 SHA、检查方式、播放起止证据、时间码、人物／背景／手部观察、结论和残留限制。模型指标不自动签发视觉通过。
- 如播放器不可用，写 `PLAYBACK_PENDING`；逐帧目检和完整解码可以记录通过，但不得称“完整播放验收通过”。
- 仅对已看过的具体样片作结论。未知人物、复杂动作、高分辨率、跨风格、音画同步仍需新样本。

## 失败状态

| 状态 | 处理 |
|---|---|
| SOURCE_REJECTED | 源错帧／滚动／静止／突变，重做源动画 |
| SOURCE_REVIEW_REQUIRED | 完整查看源帧，不能直接升级为成片 |
| FLOW_REJECTED | 有撕裂／重影，回退或缩小动作；无证据不更换默认算法 |
| ENCODE_REJECTED | 规格、时长、解码不合格，修复后从新目录重跑 |
| TECH_PASS_VISUAL_PENDING | 技术通过，视觉尚待实际检查 |
| PLAYBACK_PENDING | 缺少真实播放条件，明确保留，禁止最终视觉通过 |
