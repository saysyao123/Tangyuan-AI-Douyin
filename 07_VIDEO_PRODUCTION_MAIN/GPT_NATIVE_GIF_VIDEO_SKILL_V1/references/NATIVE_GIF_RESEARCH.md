# 原生 GIF 生成复核 · 2026-11-05

本轮基线：main `1c3aa84cd9175e45a87a3451d8292820bff3a82a`。这是能力复核和提示词修正，不发布新的生成能力版本。没有新原生 GIF 成片通过验收。

## 原目标及当前结论

原链路为：可选参考图 → **GPT 原生源 GIF** → 全部源帧审核 → 按真实时间补间 → **5.00 秒／120 帧 GIF** → 同时间轴 **5.00 秒／120 帧／24 FPS MP4** → 全帧和播放验收。保持零新增现金费用、固定人物、固定镜头、完整帧、禁止滚动拼图；不改 Work-Fisher 总流程。

当前主要阻塞在新原生 GIF 的取得，不能由 Python 编码或多写提示词解决。此前带参考图请求失败；本轮补测不带参考图仍返回相同 HTTP 400：`GIF output is not enabled for this request.`。因此“仅因为带了参考图”不足以解释失败。后端模型、账号权限或执行入口的具体原因尚未查明，不能推断全部 Plus 或全部网页端都不能生成 GIF。

三张 PNG 的咖啡馆眨眼实验保留其眼部效果和客观文件参数记录，但不作为原链路成功。需要恢复的是原生源动画，不能通过补交一个静图组装 GIF 消除这个缺口。

## 下一次原链路复测的具体条件

1. 在当次真正支持原生GIF输出的既有免费入口执行。开始前核验工具范围；同一“未启用”错误出现后停止无依据重复请求，保留完整请求和错误。当前没有可由本脚本打开服务端GIF权限的已验证办法。
2. 首轮只做单人、固定镜头、轻呼吸和一次慢眨眼。沿用已确认角色与画风；暂停将抬手接触作为默认验收动作。抬手经验和失败记录保留，待微动原链路通过后另测遮挡。
3. 若当次上限仍为16，可尝试原生16帧×310ms≈4.96秒；它是**待复测的请求规格**，不是已生成素材。解码后以实际帧数、逐帧时长和画面为准，绝不承诺16个不同姿态必然返回。能使用原30帧路线时，也必须重新取得实际文件与生成记录。
4. 保存原始返回文件；先运行 `--inspect-only`，查看全部完整源帧，再决定是否补间。若出现换脸、背景漂移、拼图或动作瞬移，源阶段拒绝，不能先凑120帧。
5. 源审核通过后，继续使用现有 `gif_to_video.py` 的时间映射和保守Farneback路径；产出GIF120帧累计5000ms，MP4恒定24FPS，分开报告真实源帧、输出采样、补间和末尾停留。GIF的40/50ms延时近似24FPS，不把GIF称为精确恒定24FPS容器。
6. 查看全部输出帧并完整播放，尤其眼睑、面部、发丝和背景；清晰度不足按原生尺寸披露。只有源动画、输出格式和视觉三关均通过，才记新原链路演示通过。

本轮对假设16×310ms输入仅运行了现有 `timeline_map` 函数：映射到120个输出位置得到8个源时刻采样、105个中间位置、7个末帧停留；总时长从4960重定时到5000ms，倍率约1.0081。**这只是时间计算，不是生成或画质测试**，也不意味着有105个有效新动作。完整脚本当前导入缺少cv2，本轮未重跑整套媒体回归；历史37/37证据不改写为本轮成绩。
