# 执行规则与门禁（外部控制层）

## 原始目标
忠实运行用户提供的 Work-Fisher `korean-thriller-asset-to-video` Skill，作为目前小说影视化、AI剧情短视频和视频生成的**默认主线**；用真实视频测试验证其效果，再增量调整。

## 不变约束
1. 原版文件位于 `original/`，不直接改写；修改建议存新版本并保留差异、实测证据。
2. 不改变原著已明确事件、台词、人物关系、动作对象、因果和时间顺序；必要改编先说明。
3. 严格按角色整体确认 → 场景整体确认 → 图片实际检视 → 视频提示词推进。用户明确限定只做某阶段时尊重其范围。
4. 人物默认单人、全身、基础形象；场景默认无人，关键道具独立描述。图像中的剧情状态由后续分镜决定。
5. 角色 `C01`、服装 `C01-V01`、场景 `E01`、道具 `P01`、声音 `S1` 连续编号；换场或衣服状态变化要记录。
6. 原版视频提示词基线：**15秒、3–4编号镜头、每镜1–2机位**，默认A，B必须补充信息；固定五字段、禁文字规则、声音声明。若实际生成模型有不同限制，另外记录适配，原版不改。
7. 生成失败只返工问题镜头，不因局部反馈推翻整片；不跳过质量检查。
8. 正常不需用户维护技术状态；由执行 Agent 更新内部状态、交付本阶段结果。

## 阶段与实际验证层次
- `SCRIPT_ANALYSIS`：书籍文本与选段核对；不假定用户授予对外商业改编许可。
- `CHARACTER_REVIEW`：角色提示词已完成，等待整批批准。
- `SCENE_REVIEW`：场景/道具提示词已完成，等待整批批准。
- `AWAITING_IMAGES`：用户/工具已生成的真实图像待齐备及检视。
- `VIDEO_READY`：参考图齐备，可完成五字段视频提示词。
- `VIDEO_GENERATING`：进入真实模型执行，必须记录服务、耗时、参数和成功失败。
- `VIDEO_QA`：检查动作/形变/连续性/声线/镜头/音画同步。
- `DELIVERED`：实际文件存在，技术与内容检查均通过。

文案完成、JSON已提交、模型的旧预览元数据不能推进状态为 `DELIVERED`。用户明确要求跳过某一制作环节时，应如实更新跳过原因。

## 试验与优化
第一条书籍片段以**原版基线**为主，除必需的模型/时间/画幅适配外，不同时调整多项规则。记录每轮：目标/模型版本/参考图/提示词/输出规格/人眼评价/失败原因/费用。后续优化记录在新文件，不篡改原版。

## 与旧视频系统的冲突规则
本主方案优先用于**新生成式短剧和新小说视频任务**。仓库旧 MV R3 主线及 `gossip_video_workflow` 保留作为专项资产；续作若有之前批准的硬规则和已通过测试步骤，不得默默废止。用户明确要求 Work-Fisher 为新的统一试验首选时，先在**不破坏原项目**的情况下对照试验。
