# T1.2 失败与修正

1. 独立复核发现：仅结构/版本/脚本校验不足以证明备份能恢复，空队伍会覆盖成坏档。已改为复用原生 restorePayload 的完整场景与动作预检，在 validateOnly 返回处结束，不提交世界。
2. 独立复核发现：旧读档被新请求取代的 rejected 结果可能覆盖最新提示。增加内部 superseded 结果并遵守已有 loadIntent 所有权，不改变存档格式。
3. 独立复核发现：ZIP 外层哈希与CRC不能证明内部运行文件正确；静态HTML下载URL变体导致清单失效。每种ZIP加入独立内部清单，静态变体与运行目录双向比较，增加CRC有效/外层哈希重算仍必须拒绝的反例。
4. 首轮 CI 38890667520：标题原版两反例红、修复版6单测与两端typecheck通过；浏览器备份与4种拒绝通过。随后原生quota故障测试等待保存失败超时；运行计数持续推进、零pageerror，位置未动，F5未到达游戏。原因是 Canvas 没有 tabindex，测试的 focus() 未使焦点离开父页文件框。改为真实点击Canvas后发送键盘，不改业务断言。
5. 本地一次直接Vite构建误在workspace根目录执行，报无index.html；改为reforge目录执行成功。正式构建器始终使用明确cwd，未因此改配置。
6. 基础包原有约679KB单块产生构建警告；采用上游Editor已使用的保序分块方式，最大JS约253KB；没有提高告警阈值或降低检查规则。

7. 第二轮 CI 38891163098：新增存储/导入/恢复/race/pointer项目及60秒活动路线均通过（226次移动、3615次引擎更新与成功呈现调用，P95约18.1ms、P99约19.1ms，模拟4倍CPU）。停帧恢复测试随后失败：只检查retry.hidden属性，忽略父加载层隐藏；应用正常ready分支也未重置曾经显示过的retry，导致属性残留可假通过。已修正常ready分支隐藏retry，并让测试等待实际可见按钮后核对停帧文案。未降低活动/恢复断言。另启用CDP Performance域，以真正采集堆大小；此前无指标不冒充内存证据。

8. 下载源码的干净目录复现首次误用了环境默认pnpm11及offline安装，因离线元数据不可用失败；切回交付说明固定的npx pnpm@10.17.1和frozen-lockfile。该失败不是源码构建失败，后续结果另记，不把默认工具版本当作固定构建环境。
