# T19｜审美方向批准后：从概念图到可玩游戏的执行顺序

更新时间：2026-10-17。原有T19分期不废止。用户在P1 V2展示后明确表示「这次的美术设计效果我很满意，如果全部都能按这个设计逻辑完成这个游戏，效果会很好」，批准的是**整体美术方向**，并非确认所有游戏帧、场景注册坐标、步态和可玩版本已通过。

## A. 当前可复用与真实状态

- T18 正式运行版有效，现有两幕九张地图和已通过的操作/旧存档修复均为基线，保留该版本与其 `RELEASE.json` 回退标识。
- P0问题清单已保存于 `docs/T19_PROGRESS.md`。
- V2 的现代冬夜屋、深色冬装成年主角、浅色上衣红围巾孩童、可识别NPC/家具、柔和局部暖光与冷雪夜，以及传统等距像素画风，构成批准的视觉DNA。
- 最近几轮新增的雪夜庭院、灯火面馆、雪路、幻想古树、NPC/物件素材板仅是**概念图**；没有证据证明已导入本仓库的可运行 `RLE` 或更新私有 Site，不能写为已完成。
- V2 原生像素试缩验证指出衣料和脸部细节丢失；高分辨率概念图不能直接整张缩为320×200充当地图，更不能改变原故事事件或场景机制。
- 以上新参考图存在聊天上下文/会话附件，**GitHub尚无对应原生图集或生产用二进制文件**。下一轮实施需先取得这些文件的可靠可访问路径并核对内容；找不到时不要声称已复用，也不要盲目重复生成整套。

## B. 不可变项目规则

- 不扩写后续剧情、不重排已认可的两幕故事/任务/数值，不另建引擎、不做EXE。
- 不改原 `projectId`、SAVE12、/chapter/连续入口、T18点击地面与opaque像素交互/键盘接管/旧档家具恢复；不覆盖正式 Site 的原稳定版本。
- 先维持320×200、2:1等距坐标、现有调色板/索引RLE、四斜向×三姿势；若 P2 发现细节密度无法达到批准的美术效果，须交320×200实景证据及高一档分辨率对照，说明修改引擎、UI、点击碰撞、成本与存档的影响，再请求批准，不先升级全局画质。
- 民俗/雪景概念图中出现的建筑、商户或幻想元素只能用作**美术表达**，不能默认为书籍新增场景/人物/商店；以当前合法游戏场景与私有故事为权威。
- 只新绘原创素材，参考原版仙剑的比例、遮挡、材质和视图构成，不发布原商业图/原书私有对白。

## D. P2首个可执行小任务（严格低额度）

1. **取真值**：仅打开 T18旧屋场景真实截图和 `tools/t16/opening.mts` / `tools/t18/opening.mts` 当前 `home-room`，记录320×200视窗、床/电视/柜/窗/餐桌/灯/水盆/门的渲染坐标与遮挡/碰撞/点击脚印；不要重查九图。
2. **拆视图而非粘一张概念图**：按后台墙/地砖、可碰家具、前景遮挡、交互道具、环境光源五层分别输出，保持原矩形/菱形点击语义。
3. **先做最小“房间三件套”**：墙地接口、床/电视及接地阴影、暖灯与窗冷光，在**原320×200入场镜头**真实渲染;与T18同机位人工比对，小图不成立则局部返修。
4. **再加两主角身份帧**：只做两名角色的四斜向站姿精修，确认阴影、比例、颜色与房间统一；然后才补全4×3步态，不能提前扩至所有NPC。
5. **测试受影响功能并交给用户看**：针对T18旧屋已有游戏逻辑，仅检查视觉替换关联的导航、点击和旧档；静态截图/短视频与失败点分开记录。
6. **进度同步**：把本次素材SHA/源位置、实际运行图、确认人/结论及未验证点补回 `docs/T19_PROGRESS.md`，成功后等待用户可玩审美验收，再执行P3/P4。

## E. 最重要的风险与停工判据

- **概念图很美≠320×200原生地图同样美**。这是P2第一优先级的技术与美术风险；不得用大图视觉通过代替原生分辨率成品验收。
- **概念里雪院、古树等不一定等于当前剧情地点**：任何新增主体/商店/神社先对照现有场景实体和剧情cue，不因图片有就新增游戏逻辑。
- **整体背景一张平铺会破坏点击穿透/遮挡**：必须明确图层、opaque命中与脚底锚点。
- **静态完成不等于动画完成**：角色四向、真实步态、轻环境变化分门验收，控制低配设备成本。
- **不要虚构工作完成度**：只有实际原生运行和证据才能记“P2通过”；本文件是接下来实施的工作指令，不是已经完成的P2报告。
