唯一目标仍为 **保留 T22 网页和 T23 引导，在 Type PAL 原生游戏完成第一幕 fair → backstage → street → courtyard 的高精细场景、NPC、角色动作与日式 RPG 路线，交付实际可玩网页**。先前T24氛围叠层及T25程序石砖/建筑明确审美不通过，绝不可继承为正式美术。

## 本次真实制作与版权

- 已将之前得到用户认可的 **T19 P1 V2 两主角四方向原生像素站姿** 作为可追溯的**原始美术文件**写入 GitHub：`art/t26/adult_4dir_approved.png`（Git blob `d87af2cb906bcf3621e415a281f2fe213e4ee4e6`）、`art/t26/child_4dir_approved.png`（Git blob `04c7a4e23461361e7a479c7b89648f87d0bc0221`）。这些文件来自本项目既有原创素材，并非未经许可的《仙剑》商业图。
- `tools/t26/build_approved_leads.py` 使用固定项目的256色调色板，成年主角36×56、孩童32×44，四方向×每方向三帧，编码为与上游`encodeSpriteChunk`一致的gzip RLE，**逐像素解码一致性检查**。只替换`sprite.hero`/`sprite.child`两份字节和`assets/index.json`中的哈希/长度。人物关系/剧情/地图/SAVE12/输入/T22主页面字节不变。
- 三帧动作仅是基于已认可站姿构造的**行走候选**：髋部以下两条腿各自1像素偏移；**这一版步态还未达到用户认可的真实重心、反向摆臂标准，不能因为格式通过便批准角色动画**。不将此候选发布到原Site。
- CI：`.github/workflows/book_rpg_typepal_t26_leads.yml`先克隆已恢复原网页与引导的`t23-journey-preview`；Pillow转换/项目schema检查/只变更两精灵对比，再用Chromium加载四场景与原网页对照屏幕。当前状态以实际CI为准。

## 下一个真正不可省略的艺术门

T26只推进角色**真实文件链路**，不足以满足完整第一幕。必须转向由已获批准的高细节视觉母版拆分的美术正式层（建筑壳体/屋顶/门窗/地面连续纹理/人设一致/前景遮挡），坚持和原生地图锚点匹配。角色动态须实机逐帧验证抬脚→落脚→蹬地→重心转换、四向方向不漂移，必要时提高**美术显示**分辨率而不变更游戏碰撞与SAVE12。全部四图、美术、完整剧情和交互验收后再发布用户最终网页。任务未完成前，不把单项技术通过标为项目完成。
