# S0–S7 作业链（每个阶段有独立验收）

| 阶段 | 固定输入 | 主要产物 | 必须通过的门禁 |
|---|---|---|---|
| S0 素材与授权 | 用户书籍/文件、希望制作的范围 | source_manifest.json + chapter_index.json + rights.md | 来源可核对、章节完整度明确、公开分发权限确定 |
| S1 原著深读 | 有序章节 | fact_ledger.json、timeline.json、character_relations.json、locations.json、unresolved.md | 人/地点/因果/时间引用有章节来源；事实与新增剧情分离 |
| S2 游戏导演 | S1 数据与冻结机制表 | game_bible.md、beat_graph.json、角色游戏卡、scene_list.json、quest_graph.json | 主角行动目标明确；每段有可操作的交互；故事入口可通往结局；玩家不被动看长对白 |
| S3 素材导演 | S2关卡、人设和背景规范 | assets_manifest.json、设计图/人物帧/地图、授权来源 | 视觉一致；原作者资产不混入可发行工程；缺资源列明，不假装完成 |
| S4 游戏内容编译 | S2/S3 结构化数据 | 独立 game.json 内容包 + reports/content_gate.json | IDs/关联/碰撞/关卡/对话/战斗/结局引用完整 |
| S5 引擎适配与构建 | 符合合同的内容包 | demo.html / Type PAL adapter 输出、构建日志 | 真实可打开，可操作、有剧情和战斗；官方引擎接入另行实测 |
| S6 试玩与 QA | 构建、测试案例 | qa_report.json、录像/截图、缺陷单 | 新游戏→对话→探索→战斗→结果→存读档→结局，完整闭环 |
| S7 发布/归档 | QA报告、权利清单 | 可玩版本、变更日志、阶段经验回填 | 授权、可再现构建、回滚、第二作品零改动复用路径 |

### 阶段门禁
- S0 不通过：停止外传/发布受保护原文，只能做合法技术研究或使用作者提供的概要。
- S1 不通过：不能写下一轮 NPC 台词；定位缺章节/矛盾事实，返回章节调查。
- S2 不通过：不能大量生图或开始建全图；先做“玩家行为”与剧情因果闭环的纸面回放。
- S3 不通过：用原创占位符继续**私人内部原型**可以，但严禁打包成已完成商品。
- S4 不通过：停止运行并修复结构来源，不给客户端填默认假的结局。
- S5 不通过：提交日志并保持 BLOCKED，不能以截图替代实际可操作。
- S6 不通过：记录复现步骤，修完重跑此前通过的所有关键事件。
- S7 不通过：交付内部测试结果、明确不具备公开发布条件。

### 长篇分卷原则
1. 建立稳定 chapter_id 和原文定位符，不直接以字节偏移作为永久身份。
2. 分卷读取后保留“事实账本”及时间线，可复核原文引证。人物同名消歧，地点进出关系与物品前置状态。
3. 选一个故事弧作为垂直切片，保留宏观结局方向和关键人物动机。
4. 同一本书之后扩章节只扩内容文件，不改引擎 API。
5. 对当前书和下一书分别用自动回归，防止样本过拟合。
