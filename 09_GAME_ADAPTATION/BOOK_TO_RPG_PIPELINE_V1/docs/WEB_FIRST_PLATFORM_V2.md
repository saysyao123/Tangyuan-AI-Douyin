# 书籍 → Type PAL 网页游戏系统 V2：目标合同

## 北极星
用户上传有使用权的书籍后，AI将原著章节转成可以操控/对话/打怪/升级/存档的**仙剑98式RPG**；所有编辑与游戏最终在网页上完成。重写原版 Windows DLL、打包EXE、不受控发布原版权素材均不是目标。

## 两个实际网页界面
- **制作工作台 Editor**：左侧项目场景/人物/事件/技能/任务资产列表，中间编辑地图/角色/故事事件，右侧问题检查和保存。沿用 Type PAL Editor 官方实现，不另开第二套平行UI。先在用户本地浏览器创建/编辑工程；云端多人协作和用户系统未来另开卡。
- **玩家页面 Reforge**：载入已验收的独立故事工程，按经典仙剑探索/明雷接触战斗/回合菜单/对话/物品/存档、剧情。以 Type PAL Reforge 真实运行作为产品验收，不再以本项目轻量 HTML 作为“正式作品”。

## 贯通数据
原书 `BookSource` → S1事实与角色索引 → S2节拍/任务/队伍/关卡 → `StoryGame IR` (必须带 provenance) → S4内容编译器 → 官方 content22 工程（manifest、scene/map indexes、actors/skills/items/dialogue/events、locale、Asset Catalog）→ 浏览器游戏。
数据转换**单向且幂等**；浏览器人工修改后的内容成为作者工作副本，不允许再次运行AI时覆盖。
唯一 canonical 真源是可导出的 Type PAL 工程文件树；AI IR 可作为制作证据与重编参考，不能在运行时和编辑器中变成两份互相冲突的真相。

## 原机制冻结
- 世界：菱形斜视角、场景地物遮挡、移动/碰撞、NPC自动+交互触发、可见敌人和世界状态。
- 角色：队伍、动作精灵/战斗精灵、表情立绘、HP/MP、攻击/守备/灵力/身法、等级、技能和装备、出/入队及援护合击。
- 战斗：仙剑式命令式回合、技能/五灵/中毒与状态、敌人AI、战斗结算和增长。
- 剧情：世界状态flags、触发条件、对话、物品、场景进出、非循环死锁、演出、结局。
- 内部用更现代的数据结构可接受；玩法输出若偏离需实机证据与用户明示批准。

## UI/网页发布实践
- 编辑器和游戏各有专属网页入口；必须 HTTPS 或本机可信 localhost，以支持权限文件操作。
- 作者本地目录/工程 ZIP 保存，不能将 GitHub Pages 当有服务端存储的主机。
- 交付的是独立项目工程/浏览器构建；若静态部署，需要将工程随静态发布文件携带并正确映射，或在构建时内联/预载。
- 第三方GPLv3/音色库/字体/音乐许可逐项审计，尤其不把 Type PAL demo 内部分 PAL 派生素材当新故事的预制素材。
- 低配PC：较重的依赖安装、构建与脚本自动测试由 GitHub Actions 执行；浏览器负责可视编辑和验收。免费的公网静态托管视公开仓库/GitHub Pages的使用条件；不承诺不限量资源或自动扩缩容。

## 分段验收目标（与原S0–S7兼容）
- **T0 上游浏览器源码固定与构建**：pin commit、源目录许可审计，云端执行 package typecheck、editor/reforge build，必要时非版权页面的浏览器冒烟。新增 `evidence/TYPE_PAL_P0_*.md`。
- **T1 无仙剑素材的独立工程**：创建一位原创主角、原创地图、NPC交互、一个明雷怪物、基本战斗、存档；由 Type PAL Editor 打开/保存/重开、Reforge真正试玩，截图+日志。**不能拿projects/demo/e2e-own直接宣称原创版权全部清理**。
- **T2 AI游戏编译器**：把已有 `examples/lantern-inn/game.json` 映射为 content22全部所需文件，角色/地图/事件/资源引用闭包，连续两次相同输入产物完全相同；创建脚本fail-loud且不破坏保存后的人工修改。
- **T3 网页端作者编辑闭环**：浏览器 UI 修改一次NPC台词/地图，再保存、重新打开、试玩看到修改，回归测试；不依赖重复运行生成器覆盖用户编辑。
- **T4 网页独立发行**：在干净部署环境浏览器从首屏到结局、可存档，静态CDN/Pages不偷读本地文件；许可证与内容版权清单全部通过。
- **T5 新书生产**：保留用户之前S0–S7阶段门禁，再用第二本书仅换内容包证明无游戏机制更改。
