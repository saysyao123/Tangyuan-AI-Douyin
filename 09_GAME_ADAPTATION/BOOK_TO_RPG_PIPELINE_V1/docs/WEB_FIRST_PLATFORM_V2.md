# 书籍 → Type PAL 网页游戏系统 V2：目标合同

## 北极星
用户上传有使用权的书籍后，AI将原著章节转成可以操控/对话/打怪/升级/存档的**仙剑98式RPG**；**第一阶段制作、编辑、试玩和发行均优先采用浏览器网页**。暂不重写原版 Windows DLL、不在现阶段制作EXE，也不发布原仙剑受保护素材。**长期目标允许在网页游戏成熟后复用同一引擎和内容封装Windows EXE**，而不是重新复刻游戏。

## 两个实际网页界面
- **制作工作台 Editor**：左侧项目场景/人物/事件/技能/任务资产列表，中间编辑地图/角色/故事事件，右侧问题检查和保存。沿用 Type PAL Editor 官方实现，不另开第二套平行UI。先在用户本地浏览器创建/编辑工程；云端多人协作和用户系统未来另开卡。
- **玩家页面 Reforge**：载入已验收的独立故事工程，按经典仙剑探索/明雷接触战斗/回合菜单/对话/物品/存档、剧情。以 Type PAL Reforge 真实运行作为产品验收，不再以本项目轻量 HTML 作为“正式作品”。

## 贯通数据
原书 `BookSource` → S1事实与角色索引 → S2节拍/任务/队伍/关卡 → `StoryGame IR` (必须带 provenance) → S4内容编译器 → 官方 content22 工程（manifest、scene/map indexes、actors/skills/items/dialogue/events、locale、Asset Catalog）→ 浏览器游戏。
数据转换**单向且幂等**；浏览器人工修改后的内容成为作者工作副本，不允许再次运行AI时覆盖。
唯一 canonical 真源是可导出的 Type PAL 工程文件树；AI IR 可作为制作证据与重编参考，不能在运行时和编辑器中变成两份互相冲突的真相。

## 原机制冻结
- 世界：菱形斜视角、场景地物遮挡、移动/碰撞、NPC自动+交互触发、可见敌人和世界状态。
- 角色：队伍、动作精灵/战斗精灵、表情立绘、HP/MP、攻击/守备/灵力/身法、等级、技能和装备、出/入队及援护合击。
- 战斗：仙剑式命令式回合、技能/五灵/中毒与状态、敌人AI、战斗结算和增长。
- 剧情：世界状态flags、触发条件、对话、物品、场景进出、非循环死锁、演出、结局。
- 内部用更现代的数据结构可接受；玩法输出若偏离需实机证据与用户明示批准。

## UI/网页发布实践
- 编辑器和游戏各有专属网页入口；必须 HTTPS 或本机可信 localhost，以支持权限文件操作。
- 作者本地目录/工程 ZIP 保存，不能将 GitHub Pages 当有服务端存储的主机。
- 交付的是独立项目工程/浏览器构建；若静态部署，需要将工程随静态发布文件携带并正确映射，或在构建时内联/预载。
- 第三方GPLv3/音色库/字体/音乐许可逐项审计，尤其不把 Type PAL demo 内部分 PAL 派生素材当新故事的预制素材。
- 低配PC：较重的依赖安装、构建与脚本自动测试由 GitHub Actions 执行；浏览器负责可视编辑和验收。免费的公网静态托管视公开仓库/GitHub Pages的使用条件；不承诺不限量资源或自动扩缩容。

## 分段验收目标（与原S0–S7兼容）
- **T0 上游浏览器源码固定与构建：PASS（2026-10-16）**：固定SHA、官方content typecheck、Reforge和Editor构建、Chromium打开编辑器、上游e2e-own工程加载并渲染Canvas。对应 [实际云端run 38853212658](https://github.com/saysyao123/Tangyuan-AI-Douyin/actions/runs/38853212658)，见 `evidence/TYPE_PAL_P0_BROWSER_VERIFIED_20261016.md`。这仅证明官方开发测试环境的网页两端运行，不证明独立原创内容的编辑保存闭环。
- **T1 无仙剑素材的独立工程**：创建一位原创主角、原创地图、NPC交互、一个明雷怪物、基本战斗、存档；由 Type PAL Editor 打开/保存/重开、Reforge真正试玩，截图+日志。**不能拿projects/demo/e2e-own直接宣称原创版权全部清理**。
- **T2 AI游戏编译器**：把已有 `examples/lantern-inn/game.json` 映射为 content22全部所需文件，角色/地图/事件/资源引用闭包，连续两次相同输入产物完全相同；创建脚本fail-loud且不破坏保存后的人工修改。
- **T3 网页端作者编辑闭环**：浏览器 UI 修改一次NPC台词/地图，再保存、重新打开、试玩看到修改，回归测试；不依赖重复运行生成器覆盖用户编辑。
- **T4 网页独立发行**：在干净部署环境浏览器从首屏到结局、可存档，静态CDN/Pages不偷读本地文件；许可证与内容版权清单全部通过。
- **T5 新书生产**：保留用户之前S0–S7阶段门禁，再用第二本书仅换内容包证明无游戏机制更改。

## 2026-10-16 决策：先网页验证，桌面 EXE 后置

用户明确裁决：**先专注 Type PAL Reforge 网页 RPG 的真实体验、编辑闭环和书籍转换；当网页成品足够好，再考虑 Windows EXE。** 本阶段不为打包桌面程序额外发散系统需求。

### 未来桌面封装方案（尚未执行）
- **默认候选：Tauri 2**。将网页构建静态资源和游戏内容包放入桌面程序，通过Windows WebView2显示；可构建安装程序。必须逐项验证 WebView2 版本、资源离线访问、音频播放、本地持久存档和文件读写权限；体积优势取决于WebView2是否随系统提供或需离线捆绑。官方：https://v2.tauri.app/distribute/windows-installer/
- **备选：Electron + Electron Forge**。嵌入Chromium并可制作 Windows EXE/安装包，通常包更大，但浏览器行为更一致，若 Tauri 音画兼容性不符合要求再使用。官方：https://www.electronjs.org/docs/latest/tutorial/tutorial-packaging
- 两条路线均应**复用同一个 Type PAL Reforge 游戏逻辑、content22工程与原创资源**；桌面壳仅封装渲染、读写文件、存档位置和系统权限，不复制或重新实现地图、对话、战斗/成长。
- **网页版保存方案不能直接视为桌面版可用**。浏览器FSA/IndexedDB、本地目录和Tauri/Electron权限模型不同，须做适配层和存档迁移测试，不能在打包后丢存档或丢离线素材。
- Windows发行还需安装/卸载、中文字体、音频/视频资源离线打包、全屏与键盘/手柄测试、GPLv3遵循、第三方声音/字体授权；公开发行建议代码签名（可能产生费用）。不承诺零额外费用的已签名发行。
- 若上游静态独立可玩包还未完工（当前A8未验收），桌面壳也不能替代它：**先T1-T5网页通过，再设 T6 Desktop packaging gate**。

### T6将来的验收条件
1. 同一版本游戏网页和Windows桌面版，剧情/战斗/人物数值/地图/任务结果保持一致。
2. Windows干净环境安装或解压后，**断网**能从开场玩到结局；重启后存档仍在。
3. 无Vite开发服务器、无隐藏的本地 `/projects` 代理依赖；完整素材与字体合法打包。
4. 生成真实EXE或Windows安装程序，并交付SHA256、安装和卸载记录、缺陷报告；如果未跑Windows实机不标PASS。
5. 仅游戏玩家版打包；网页内容编辑器仍作为主作者平台，除非有明确需求单独决定是否做桌面编辑器。
