### 本轮机制研究进一步锁定的细节
- `global.h PLAYERROLES` 明确含 `CoveredBy`（援护角色）、`CooperativeMagic`（合体技）、不同角色声音与装备用量，决定人物设计必须兼顾“人物关系×战斗功能”。
- `script.c` `PAL_InterpretInstruction` 处理 1 opcode + 3 operands；不能仅抽取对白就声称完整剧情可转；必须建事件状态/条件/分支账本。
- `fight.c` 包含 PAL_CLASSIC 与非经典战斗调度路径；**98柔情版的真实节奏、概率、数值需G0运行后再冻结，不得任意选择ATB**。
- 事件/精灵有叠层、自发脚本和脚本接管的隐含时序；对新内容应保留观感，同时通过显式脚本避免程序旧bug。
- 底层程序历史限制（固定容量、字节下标、特定地图编码）是实现细节，不是下一部书的设计标准。
- 上传包历史观察：15 MKF、总2373资源块；Sss.mkf结构分出295条8字节场景记录、43557条8字节脚本记录；**并未完成全部记录含义的解码**。

### 下一阶段必须做的原版实证（按优先级）
1. 使用本次98版资源实测开局、菜单、NPC交互、第一次战斗、队伍、存取档，记录屏幕/操作。
2. 从 Sss.mkf 提取 opcode 频次、跳转范围、不可解释操作与死循环的真实清单，并交叉验证SDLPAL指令解释。
3. 从 Data.mkf / 角色表取得原版数值、装备/技能学习/毒/战场抗性矩阵，并建立机理对照测试。
4. 对一位主角、一位同伴、一场战斗、一处NPC演出制作“来源→规则→测试→修复”的闭环。
5. 运行不使用原版权资产的独立内容包，再逐渐提升与仙剑的可感知一致性。

**当前未完成上面1–5的全量实测。正式Type PAL/Reforge引擎适配不得因自制轻量demo通过便标记通过。**
